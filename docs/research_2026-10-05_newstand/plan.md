# 新スタンド対策: stand dropout と NEW_STAND トークン — 事前登録（2026-10-05）

結果を見る前に書いて push する。判定規則と群は、測定を始めた後に変えない。

## 背景
- 2026 年の Jan+Jul には、2025 年に出てこないスタンドが 1,589 行（主に EDDM 103〜108、EDDF の一部）、2025 年に 30 行未満のスタンドが 2,708 行（主に EDDF T3）ある。
- 09-28 の模擬テスト（`docs/osm_stand_2026-09-28/results.md`）では、スタンドの 20% を学習から抜くと、その行の MSE が約 12,900 s² 増えた（RMSE で約 195 → 225）。
- 今のモデルでは、学習に無いスタンドは、学習で一度も見ていないカテゴリ値として LightGBM に入る。どの分岐に落ちるかは、学習の都合で偶然決まる。
- **見込みの上限**: ランキングの約 1% の行が「知っているスタンド」並みに戻ったとしても、LB で約 −0.3 秒。現実的には −0.05〜−0.15 秒 [推論]。

## 変更（`stand_dropout`、既定 0 で既存の id は不変）
- 学習行の 5%（MVT_ID の CRC32 で選ぶ）で、`STAND_mvt` を `__NEW__` に置き換える。
- その行のスタンド単位の参照値（`ref_p10/p20/med/n`）は空にする。`ref_p10_fb` は空港×滑走路×時刻、無ければ空港の値で埋め、`ref_missing` は 1 にする。
- 予測側では、学習側に無い (空港, スタンド) の行を `__NEW__` に置き換える。
- 置き換えは fold 特徴量を作った後に行う。だから OSM の距離は本当のスタンドから計算される。

## 群（すべて `main_flseq_osm_nolirf` + `folds: [forward]`）
| 群 | 追加の設定 |
|---|---|
| ns_base | なし |
| ns_drop | `stand_dropout: 0.05` |
| ns_base_u | `sim_unseen_stands: 0.2` |
| ns_drop_u | `sim_unseen_stands: 0.2` + `stand_dropout: 0.05` |

## 判定（3 つとも満たせば採用候補）
1. **学習に無いスタンドで改善する**: 模擬テストの未知スタンド行（forward の検証行のうち、`unseen_stand_mask(share=0.2)` に当たる行）で、ns_base_u → ns_drop_u の K=200 の 95% CI が改善側で 0 を除外する。
2. **未知スタンド行の全行（K=0）でも悪化しない**: 同じ行で、K=0 の差が 0 以下。
3. **知っているスタンドを悪くしない**: 通常の forward で、`prc.compare ns_base ns_drop` の K=200 の CI の上端が +0.10 秒以下。

参考として、厳格チェック（STRICT VERDICT）と空港別の結果も載せる。判定には使わない。

## 採用されたら
- 本番の matched member に `stand_dropout: 0.05` を入れて全 fold で走らせ、通常の `make compare` にかける。
- 期待値が小さいので、他の作業より優先はしない。
