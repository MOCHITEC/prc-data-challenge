# 採否判定の強化: 厳格チェックと凍結ホールドアウト（2026-10-05）

`python -m prc.compare A B` に次を追加した。従来の VERDICT（曲線のみ）は変えず、横に STRICT VERDICT を出す。

- **厳格チェック**: 全行と、悪い 200 行を除いた場合の両方で、次の 3 つがすべて成り立つときだけ ADOPT。
  - fold（jan・jul・forward）がすべて改善する
  - 7 割以上の空港が改善する
  - 空港×日のブロック・ブートストラップの CI が 0 を含まない（約 1,200 ブロック。月単位の 4 ブロックより信頼できる）
- **凍結ホールドアウト** `--holdout {include,exclude,only}`: 空港×日の 20% を CRC32 で固定する。
  - 開発中の比較は `exclude` で行う。
  - 採用を積み上げた後、まとめて 1 回だけ `only` で確かめる。
  - 既定は `include` で、従来と同じ動作。
- 注意: これまでの全実験はホールドアウトの日も見ている。厳密に未使用なのは、これから先の判断についてだけ。

## L5（CV −0.32 秒、LB +0.12 秒）での試し
| 対象 | 曲線の判定 | 厳格チェック |
|---|---|---|
| 全行 | ADOPT −0.32 | ADOPT（fold: jan −0.04 / jul −0.50 / forward −0.40、9/10 空港） |
| 開発用の日（80%） | ADOPT −0.36 | ADOPT |
| ホールドアウトの日（20%） | REJECT −0.13 [−0.39, +0.12] | REJECT（4/10 空港） |

- **厳格チェックだけでは L5 を落とせなかった。** CV の中では、どの角度から見ても一貫して改善している。
- ホールドアウトの日では効果が弱く、有意ではなかった。ただし、ここは行数が 20% しかなく検出力が低い。偶然の範囲の可能性もある（1 例だけでは較正にならない）。
- 目立つのは、テスト月と同じ季節の **jan fold で効果がほぼ 0**（−0.04 秒）なこと。2026 年 1 月の LB で効かなかったことと整合する [推論]。
- LB の差 +0.12 秒は、混合の中で 1/3 に薄めた効果（見込み −0.1 秒）と、LB のノイズとの区別がつかない大きさでもある。
