# 「スタンドを出てから各地点に着くまでの時間」の地図で off-block を推定する — 事前登録（2026-10-06、CV の前に書く）

## 0. なぜ

v39（LB 239.52）の残差の CV（4 か月・a2）で、誤差の二乗和の内訳（`results/` の 10-06 の内訳表）:
- 「stand run が無く、最初に見えたのがスタンドから離れた所」: 153,373 行、二乗和の 14.9 %、RMSE 204（base 229）
- 「stand run はあるが自スタンドではない／不明」: 130,901 行、8.7 %、RMSE 168（base 211）

今の appear は、最初の fix をスタンドまで直線距離 / 6 m/s で戻す（`t_appear_adj`）だけ。それでも重要度は上位 4 位だった。
実際の誘導路の経路や混み具合を反映した「スタンドを出てからその地点に着くまでの典型的な時間」を ADS-B から学べば、
より正確に戻せるはず。

## 1. 時間の地図（`docs/appear_tier_2026-10-05/field.py`）

- **2026 年の ADS-B だけ**から作る（ラベル無し、2025 年の CV に情報は漏れない）。
- 自スタンドを出る瞬間が見えている出発便（`t_leave_own_lo` がある便、fill の表）について、その後の地上の fix を 50 m 四方の
  マス目（空港の基準点からの局所座標）に落とし、マス目ごとに最初に入った時刻 − `t_leave_own_lo` を「経過時間」とする。
- **A**（空港 × マス目）: 経過時間の中央値。5 便以上のマス目だけ。
- **B**（空港 × 自スタンドの区画 × マス目）: 自スタンドの座標を 400 m 四方の区画に落とし、区画ごとに同じ中央値。5 便以上のもの。

## 2. 新しい列（各便、2025 年・2026 年とも）

- `t_appear_fA` / `t_appear_fB` = `t_dep1` − （`t_dep1` の fix のマス目の A / B の経過時間）。
- `t_run_fA` = stand run の始まり（`t_move_lo` − `stand_dur`）− （stand run の位置のマス目の A の経過時間）。
  stand run が自スタンドの 50 m 以内のとき（本物のスタンド）は空にする。
- `fA_n`、`fB_n`（そのマス目の便数）。
- 時刻の 3 列は、既存の列と同じく MVT − t、MVT − t − base、t − AOBT_3 にして入れる（9 列 ＋ 2 列）。

## 3. 群（4 か月・a2・`cv_months.py` と同じ fold、**v39 と同じ V2 の設定**、appear は fill の表）

| 群 | 列 |
|---|---|
| cur（今の v39 の残差に相当） | stage 1 ＋ appear（fill） |
| field | cur ＋ 新しい列 |
| fshuf（対照） | cur ＋ 新しい列を空港の中で行の間で並べ替えたもの（時刻は各行の MVT からの差として並べ替え） |

## 4. 判定

**採用** = field が cur と fshuf の両方に対して、全行の RMSE の差の日単位 95 % CI が改善側でゼロを除外すること。
「stand run 無し・離れた所で最初に見えた行」「stand run が自スタンドではない行」と空港ごとの差は説明用。

採用なら、P = cur、A = field の最終モデルで差分を作り、v39（その時点の最良の版）に `apply_delta.py` と同じ方法で載せた候補を作る。
提出するかはユーザーと相談する。
