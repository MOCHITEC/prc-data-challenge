# 他チームの「書き写し・照合できない便」系アイデアを私たちのデータで測定（2026-10-05）

スクリプトとログはスクラッチ領域の `measure/copy/` にある（s1_unmatched.py、s2_matched.py、s3*_dist*.py、s4_stab.py、s5_drift.py、s6*_eval*.py）。
本文はサブエージェントの報告を要約したもの。

## 定義と換算
- **echo**: |BLOCK − SCHED| ≤ 60 s。
- **LB 換算**: ΔRMSE_LB ≈ ΔMSE_全体 / (2 × 250)。
- **2026 年の行の内訳**: 照合できた行 98.5%、照合できない行 1.53%、そのうち LIRF の照合できない行 0.11%（383 行）。
- **base**:
  - 照合できた行: harness の base（RMSE 261）と、カテゴリ変数を加えた `yall`（RMSE 235.6）。
  - 照合できない行: model B に似せた月抜き OOF（RMSE 1,094）。
  - どれも本番（v23 系）より弱い。

### 補足
- 1 で、混合をせずに ŷ_normal だけを LIRF で使うと +7.06 s 悪化する。効いているのは混合そのもの。
- 以前のメモ `lirf-matched-fill.md` の S7（照合できた行で、穴埋めかどうかを当てられるか）への答えは「当てられる」（AUC 0.857）。
- 1・2・3 はどれも LIRF に効く案なので、効果は足し算にならない。組み合わせた効果はまだ測っていない。
- 本番のパイプラインで forward と Jan/Jul を測ってから採否を決める。

## 本番への実装案
1. **混合**:
   - 学習用の fold で echo の分類器を作る（model A の列を使う）。
   - model A を echo でない行で学習し直す。
   - LIRF の照合できた行は、`_lobt_bound` の前で p·ms + (1−p)·ŷ_nonecho にする。SCHED が LOBT の範囲の外なら p = 0。
2. **G モデル**:
   - `predict_fold` で、fold ごとに LightGBM を 1 本追加する（LIRF の両 lane の行、`cols_b`、目的変数 ms − y）。
   - 付け替えを元に戻した後で λ 混合する。
3. **echo 率**:
   - `fit_encodings` / `attach_encodings` に航空会社の表を足す（model B だけが使う）。
   - 学習側の値は fold 外から作る。
