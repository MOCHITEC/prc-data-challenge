## 学んだこと

1. **学習とテストで同じ列が違う計算になっていないか**を、平均の変わらない列が年を見分けるかどうか（adversarial validation）で
   探せる。今回の一番の収穫はここから出た。CV では見えない（CV の検証行も 12 か月の窓で計算されるので CV は楽観的になる）。
2. **尾部の数行に乗った利得は LB に乗らず、本体の利得は乗る。** 外す行数を増やしたときに利得が縮むか（mix255）伸びるか（v27）で見分けられる。
3. 未マッチ行の変更は、全行の K=200 ではなく未マッチ行の中で尾部を外した差で判定すること。

## もう一方の AI への引き継ぎ（v28 = 252.41 への組み込み。優先順は 2026-10-02 の分解に合わせて更新）

v23 のマッチ行は anchored（osm_nolirf）・plain-y・CatBoost の平均 ＋ 学習した ADS-B の残差。どちらの改善も v23 の作り方の中に入れる必要がある。

1. **窓の修正（優先: model B ＋ ADS-B 残差）**: 利得の 86 % は ADS-B の証拠がある未マッチ行にある。`main_flseq` に
   `fe_fl_rate_window: both` を足した model B（= `configs/flwin_both.yaml` の未マッチ行）を base にして ADS-B 残差を学習し直し、
   v28 の未マッチ行と比べる。マッチ行のメンバーの作り直しは利得 13 % 分なので後回しでよい。
2. **切ったメンバー**: anchored のメンバーに `matched_target_clip: 1800` を足した設定を 4 つ目のメンバーとして走らせ、
   `docs/gm_research_2026-10-01/stack_clip.py` と同じ手順（空港 × ｜c − b｜の帯ごとの最小二乗の重み、fold を外して決める）で、
   b = 3 メンバーの平均の OOF に対して重みを決め直す。ここで決めた重みは b が違うので使わない。
3. 1 と 2 のあとで、ADS-B の残差モデルを新しい b で作り直す（残差モデルは b を特徴量に使っているため）。
