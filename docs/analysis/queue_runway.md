# queue_runway: 滑走路・離陸シーケンス・待ち行列ダイナミクス

作成 2026-09-24。対象: 2025 年 training（ラベル付き DEP 2,085,047 行）と ranking.parquet（2026-01/07）。
すべての新特徴量は **ranking の DEP 行で観測できる情報だけ**（離陸時刻・RUNWAY・STAND・WTC・NM 時計・SCHED、ARR 行の全列）から作った。
学習ラベル由来の統計量（stand×runway 参照値、空港×滑走路×時の中央値）は各フォールドの学習月だけで fit した。

## 0. 要点（TL;DR）

1. **推奨セット（seq + nbr + sched_arr の 39 列）を既存 v7 相当の特徴量に足すと、`genuine` 行（taxi-time ヘッドの担当、v7 で SSE の 58%）の jan+jul RMSE が 252.92 → 250.07（−2.85 秒、CI95 [−3.43, −2.27]）**。両フォールドで改善（jan −1.07 / jul −4.09）。学習乱数だけの揺れ（別シードの base）は −0.25 秒なので、その 10 倍以上。
   全体 RMSE に換算すると **約 −1.5 秒**（§6-3）。EHAM だけ nbr 群を外す構成では −3.32 秒（検証で選んだので楽観的）。
2. 群別で最も安定なのは **滑走路シーケンス群（seq）**: 単独で −1.10 秒（jan −1.59 / jul −0.77）。主役は `hw_mean_next5`（**同じ滑走路で自分の後に離陸した 5 機の平均間隔** = 自分の後ろに詰まっていた列の密度）、`hw_excess`（先行機とのヘッドウェイから WTC ペア別の実測最小間隔を引いた超過分）、混合運用での直前・直後の着陸までの秒数。**後ろ向きより前向きの窓の方が効く**（離陸時刻は全便 ranking で既知なので使える）。
3. **近傍便の NM タクシー代理値を残差化して前後両方向で平均したもの（nbr 群）** は単独で −0.66 秒だが、seq/sched と組み合わせると効く（seq_sched −1.48 → seq_nbr_sched −2.85）。ただし **非定常**: 月平均が 0〜290 秒動き、EHAM は 2026-01 の ranking で 287 秒と訓練域（57〜160 秒）の外。EHAM では nbr を含む全 arm で +3.2〜+4.2 秒の悪化（ノイズ幅 ±1.6 の外）。
4. **スケジュール backlog**（予定時刻は過ぎたがまだ離陸していない便数。SCHED と離陸時刻だけで作れる）は NM 未マッチ行で唯一まともに効いた群（−4.9 秒、CI [−9.8, −0.8]）。ただしこの層は n ≈ 5,100 で学習乱数だけで ±7 秒動くので、確証ではない。
5. **同一滑走路の連続離陸便の残差（y − 参照値）の自己相関は 0.42**（LTFM 0.61、EHAM 0.32）。空港×時の平均で残差分散の 19〜24% が説明される隠れた混雑状態がある。しかし **base モデルの OOF 残差に残る時レベル成分を観測可能量の時平均で再現する試みは失敗**（交差フォールドで +2.3 秒悪化）。他便のラベルを使うオラクルでも上限は −9.9 秒。
6. 隠れ状態の出所は空港で違う: EGLL/EHAM/LFPG では NM の実オフブロック（AOBT_3）が物理的な混雑を追っている（時平均で corr 0.81〜0.88）。一方 **EDDF/EDDM/LEBL/LEMD/LIRF では時平均残差の 86〜96% が `AOBT_3 − BLOCK`（報告側の差）に乗っており、NM はそれを見ていない**。EDDM は genuine 行で corr(y, MVT−AOBT_3) = 0.08 しかない。これらの空港で ranking から見える混雑シグナルは、離陸シーケンスとスケジュールしかない。
7. 否定的な結果: 滑走路構成をカテゴリ（出発/到着滑走路セット）で入れると gain 上位（2.8%）なのに RMSE は +0.25 秒（jul +0.85）で過学習。外した all_nocfgcat（−2.31）は all（−1.86）より良い。構成切替直後の異常は無い（±5 秒以内）。推定オフブロック（t − 参照値）を起点にした待ち行列（qhat 群）は −0.01 秒で完全に冗長。WTC ペア単体もほぼ無効。
8. 記述的には、構成は珍しい日に大きく効く（EDDM で到着 1 本運用時 +270〜345 秒、冬季の除雪・デアイシング日と推定。その間 NM 側の MVT−AOBT_3 は平常と同じ）。カテゴリではなく「通常構成からの逸脱」フラグとして入れる価値はある（未検証）。

### 評価プロトコル

- フォールド: `jan`（valid 2025-01、early stopping 用 inner 2025-12、学習はそれ以外から jul を除いた 9 か月）、`jul`（valid 2025-07、inner 2025-06、学習は jan を除いた 9 か月）。docs/06 §9-1 に従い、採点されない forward fold は使わない。
- 学習行: `clock_src ∈ {genuine, aobt3}` かつ 30 ≤ y ≤ 7200 の 50% 無作為抽出（約 69 万行/fold）。v5 以降の混合モデルの taxi-time ヘッドに相当。
- 評価行: valid 月の全行から subset を切る。主指標は **`genuine` かつ clean（30〜7200 秒）**（v7 の SSE の 58%、ルーティングでは取れない部分）。
- base の特徴量: `prc.features` の数値特徴量 ~95 列（`_slog` 複製は除く）＋ カテゴリ（ADEP, RUNWAY, STAND, AIRCRAFT_TYPE, WTC）＋ fold 内 fit の `ref_p10/ref_med/ref_n/arh_med`。LightGBM: lr 0.08, 127 leaves, min_data 100, ff/bagging 0.8, max_bin 127, 2 threads。
- 差分は行の対ブートストラップ（300 回）。学習の乱数による揺れは `base_seed1`（§6-1）で測った。

### 2-4. 到着 taxi-in の残差（到着 stand×runway 中央値からの偏差、ARR 行は ranking でも全列あり）

既存の `arr_taxi_in_mean_30m`（生の taxi-in、in-block 時刻で過去窓）と違い、残差化し、前後両方向の窓を取り、推定オフブロック時刻 `t − median(MVT−AOBT_3 | stand, runway)` を起点にした版（`arr_ti_resid_at_bhat`）も作った。
genuine 行の y との相関は 0.03〜0.18（EGLL/LFPG が最大）。base OOF 残差への η² は 0.004〜0.005 で、新特徴の中では上位。ただし LightGBM での寄与は sched_arr 群全体でも −0.62 秒（§6）。

### 3-3. base モデルの後に何が残っているか

base の jan+jul OOF 残差（phys clean）を分解すると、空港×時の平均が残差の 8〜16%、滑走路×時で 10〜28% を占める（時あたり 20〜40 便なので、純粋なノイズでもこの比率の約 3% は出る）。

| 補正（genuine clean、jan+jul、n = 235,229） | RMSE |
|---|---|
| base（補正なし） | 252.92 |
| オラクル: 同一滑走路×時の**他便の** OOF 残差の LOO 平均 ×0.5 を加算 | 243.03 |
| オラクル: 同 ×1.0 | 244.43 |
| 観測可能量の時平均 10 種からのリッジ（空港別、jan↔jul 交差 fit）を加算 | **255.19（悪化）** |

**隠れ状態の上限は約 −10 秒**（他便のラベルが要るので ranking では不可能）。観測可能量の時平均で再現しようとすると悪化する: 観測可能量の情報は base モデルが行単位で既に使っており、時平均の残差との関係は jan と jul で符号も大きさも違う（交差 fit の R² −0.10）。
「近傍便の y が似る」強さは本物だが、ranking で見える代理変数では取れないことを数値で確認した。

## 7. モデル改善への提案（優先順）

1. **seq 群を `src/prc/features.py::context_features` の滑走路ループに追加する**（最も安定: 両フォールドで改善、単独で −1.10 秒、EHAM を含め悪化する空港なし）。すべて既存の滑走路別ループの中で閉じ、ラベルを使わない（実装は `analysis/queue_runway_prep.py::runway_sequence_features`）:
   - `hw_mean_next5` / `hw_mean_prev5`（同一滑走路で前後 5 機の平均ヘッドウェイ）、`hw_min_prev3`
   - `hw_prev_pairq`（先行→後続の WTC ペア別の実測最小間隔。ヘッドウェイから fit するのでラベル不要、ranking を含めて fit してよい）と `hw_excess`
   - バースト（`hw_excess ≤ 45` の連続区間）の `burst_len`、`burst_pos`、`burst_elapsed`、`burst_remaining`、`burst_pos_frac`
   - 混合運用: 同一滑走路の直前・直後の着陸までの秒数（`arr_same_rwy_prev_s/next_s`）、`rwy_share_pm30`
   - 注意: ヘッドウェイ系は 3 時間超を欠損扱いにすべき。ranking は 1 月と 7 月が連続していないので、1 月末の便の「次の離陸」が 7 月になる（1 月の最大 199 日）。既存の `rwy_headway_next_s` も同じ。
2. **sched_arr 群を追加する**（−0.62 秒、NM 未マッチ行で −4.9 秒）: `sched_backlog_60m`、`sched_demand_prev/next30m`、到着 taxi-in の残差の前後窓（`arr_ti_resid_*`、到着の stand×runway 中央値で残差化。ARR 行は ranking でも全列あるので、中央値は training+ranking の ARR で fit してよい）、`arr_taxiing_at_tko/aobt`（着陸済みでまだ in-block していない到着機数）。実装は `queue_runway_prep.py::schedule_backlog / arrival_state` と `queue_runway_prep2.py`。
3. **nbr 群は EHAM 以外で使う**（seq+sched に足して −1.37 秒の追加）: `nbr_rg_pm20/pm60/next30/prev30/asym`、`nbr_seq_rg_pm5`、`nbr_seq_mvt_sched_pm5`、`nbr_seq_mvt_aobt_*`、`overtaken_by_aobt`、`overtook_aobt`、`rank_shift_aobt`。残差化の基準 `median(MVT − AOBT_3 | stand, runway)` はラベルを使わないので training+ranking で fit してよい。EHAM では NaN にするか、空港×月内で標準化した版を試す（月平均のシフトを消す）。
4. 期待値: 1〜3 を入れて genuine clean −2.9〜−3.3 秒、**全体で −1.5 秒前後**（本番モデルでは −1〜−1.5 秒）。LTFM（−7.8）、LEMD（−3.8）、LIRF（−3.5）、LFPG（−2.9）、LEBL（−2.7）が主な受益者で、いずれも docs/06 の SSE 上位か NM 時計が弱い空港。
5. **構成はカテゴリで入れない**。入れるなら「その空港の通常構成からの逸脱」（例: EDDM の到着 1 本運用フラグ、稼働中の到着滑走路数の平常値との差）。
6. やらなくてよいもの: `qhat_*`、`cfg_since_change_bins`、`lead_wtc` 単体、時レベルの近傍平均による残差の事後補正（§3-3 で悪化を確認）。

## 8. 注意点と限界

- 小さな LightGBM（学習行 50% 抽出、固定パラメータ）での差分であり、本番の v12/v13 系（天候特徴量や混合ヘッドを含む）に足したときの効果は小さくなりうる。特に天候（`use_weather`）は nbr 群と情報が重なる（冬の悪天候日に近傍の taxi が一斉に伸びる）。
- jan fold の学習月から jul を、jul fold の学習月から jan を除いている（ロードを軽くするため）。本番の fast CV とは学習月が 1 か月少ない。
- nbr 群の非定常性（§0-3）: 本番で使うなら ranking の 2026-01 EHAM のように訓練域外に出る値がある。ranking 側の分布を必ず確認すること（`queue_runway_prep2.py` の出力で 2025-01 と 2026-01 の月平均を比べられる）。
- 2-2〜2-4 と §3〜§4 の参照値は 2025 年全体で in-sample に fit した記述統計。効果量の判断は §5（OOF 残差）と §6（月ブロック）で行うこと。
