# queue_runway: 滑走路・離陸シーケンス・待ち行列ダイナミクス

作成 2026-09-24。対象: 2025 年 training（ラベル付き DEP 2,085,047 行）と ranking.parquet（2026-01/07）。
すべての新特徴量は **ranking の DEP 行で観測できる情報だけ**（離陸時刻・RUNWAY・STAND・WTC・NM 時計・SCHED、ARR 行の全列）から作った。
学習ラベル由来の統計量（stand×runway 参照値、空港×滑走路×時の中央値）は各フォールドの学習月だけで fit した。

## 0. 要点（TL;DR）

1. **新特徴量 5 群を既存 v7 相当の特徴量セットに足すと、`genuine` 行（taxi-time ヘッドの担当、SSE の 58%）の jan+jul RMSE が 252.92 → 251.06（−1.86 秒、CI95 [−2.44, −1.28]）**。両フォールドとも改善（jan −1.14 / jul −2.37）。全体 LB 換算では **約 −1 秒**（§6-3）。大きくはないが、統計的には確か。
2. 群別では **滑走路シーケンス群（seq）が最も安定**: −1.10 秒（jan −1.59 / jul −0.77、10 空港中 8 空港で改善方向）。主役は `hw_mean_next5`（**同じ滑走路で自分の後に離陸した 5 機の平均間隔** = 自分の後ろに並んでいた列の密度）、`hw_excess`（先行機との WTC ペア別最小間隔からの超過）、混合運用の到着間隔。
3. 近傍便の NM タクシー代理値（`nbr_rg_*`: 近傍出発便の MVT−AOBT_3 を stand×runway 中央値で残差化、**前後両方向**の時間窓）は単独で −0.66 秒だが **非定常**。月ごとに平均が 0〜290 秒動き（EHAM は 2026-01 の ranking で 287 秒と訓練域外）、EHAM では一貫して悪化（+4.2 秒）。採用するなら EHAM を除くか、月内正規化が必要。
4. **同一滑走路の連続離陸便どうしの残差（y − 参照値）の自己相関は 0.42**（LTFM 0.61、EHAM 0.32）。空港×時の平均で残差分散の 19〜24% が説明される「隠れた混雑状態」がある。しかし **v7 相当の base モデルの OOF 残差に残る時レベル成分を観測可能量で再現する試みは失敗**（交差フォールドのリッジで +2.3 秒悪化）。他便のラベルを使うオラクルでも上限は −9.9 秒（252.9 → 243.0）。
5. その隠れ状態の正体は空港によって違う: EGLL/EHAM/LFPG では NM の実オフブロック（AOBT_3）が追従する物理的な混雑（時平均で corr(r_h, rg_h) 0.81〜0.88）。一方 **EDDF/EDDM/LEBL/LEMD/LIRF では時平均残差の 86〜96% が `AOBT_3 − BLOCK`（報告側の差）に乗っており、NM はそれを見ていない**。特に EDDM は `genuine` 行で corr(y, MVT−AOBT_3) = 0.08 しかない。こうした空港では、ranking で観測できる混雑シグナルは離陸シーケンスとスケジュールしかない。
6. 否定的な結果: 構成切替直後（`cfg_since_change_bins`）の効果は ±5 秒以内でほぼない。推定オフブロック（t − 参照値）を起点にした待ち行列（`qhat_*`）は既存の AOBT_3 起点の in-system と冗長。WTC ペア単体（`lead_wtc`）もほぼ無効。
7. 構成（到着滑走路セット）は記述的には効く（EDDM で片側 1 本運用時 +270〜345 秒 = 冬季の除雪・デアイシング日、LTFM 35L 出発×到着 34L で +164 秒）。ただし高カーディナリティのカテゴリとして入れると gain 上位（2.8%）に来るのに RMSE 改善は小さく、過学習の兆候がある（§6-2）。

### 評価プロトコル

- フォールド: `jan`（valid 2025-01、early stopping 用 inner 2025-12、学習はそれ以外から jul を除いた 9 か月）、`jul`（valid 2025-07、inner 2025-06、学習は jan を除いた 9 か月）。docs/06 §9-1 に従い、採点されない forward fold は使わない。
- 学習行: `clock_src ∈ {genuine, aobt3}` かつ 30 ≤ y ≤ 7200 の 50% 無作為抽出（約 69 万行/fold）。v5 以降の混合モデルの taxi-time ヘッドに相当。
- 評価行: valid 月の全行から subset を切る。主指標は **`genuine` かつ clean（30〜7200 秒）**（v7 の SSE の 58%、ルーティングでは取れない部分）。
- base の特徴量: `prc.features` の数値特徴量 ~95 列（`_slog` 複製は除く）＋ カテゴリ（ADEP, RUNWAY, STAND, AIRCRAFT_TYPE, WTC）＋ fold 内 fit の `ref_p10/ref_med/ref_n/arh_med`。LightGBM: lr 0.08, 127 leaves, min_data 100, ff/bagging 0.8, max_bin 127, 2 threads。
- 差分は行の対ブートストラップ（300 回）。学習の乱数による揺れは `base_seed1`（§6-1）で測った。

### 2-4. 到着 taxi-in の残差（到着 stand×runway 中央値からの偏差、ARR 行は ranking でも全列あり）

既存の `arr_taxi_in_mean_30m`（生の taxi-in、in-block 時刻で過去窓）と違い、残差化し、前後両方向の窓を取り、推定オフブロック時刻 `t − median(MVT−AOBT_3 | stand, runway)` を起点にした版（`arr_ti_resid_at_bhat`）も作った。
genuine 行の y との相関は 0.03〜0.18（EGLL/LFPG が最大）。base OOF 残差への η² は 0.004〜0.005 で、新特徴の中では上位。ただし LightGBM での寄与は sched_arr 群全体でも −0.62 秒（§6）。

### 3-3. base モデルの後に何が残っているか

base の jan+jul OOF 残差（phys clean）を分解すると、空港×時の平均が残差の 8〜16%、滑走路×時で 10〜28% を占める（時あたり 20〜40 便なので、純粋なノイズでもこの比率の約 3% は出る）。

| 補正（genuine clean、jan+jul、n = 235,229） | RMSE |
|---|---|
| base（補正なし） | 252.92 |
| オラクル: 同一滑走路×時の**他便の** OOF 残差の LOO 平均 ×0.5 を加算 | 243.03 |
| オラクル: 同 ×1.0 | 244.43 |
| 観測可能量の時平均 10 種からのリッジ（空港別、jan↔jul 交差 fit）を加算 | **255.19（悪化）** |

**隠れ状態の上限は約 −10 秒**（他便のラベルが要るので ranking では不可能）。観測可能量の時平均で再現しようとすると悪化する: 観測可能量の情報は base モデルが行単位で既に使っており、時平均の残差との関係は jan と jul で符号も大きさも違う（交差 fit の R² −0.10）。
「近傍便の y が似る」強さは本物だが、ranking で見える代理変数では取れないことを数値で確認した。

## 7. モデル改善への提案（優先順）

1. **seq 群を `src/prc/features.py::context_features` の滑走路ループに追加する**（最も安定: 両フォールドで改善、群単独で −1.10 秒）。実装はすべて既存の滑走路別ループ内で閉じ、ラベルを使わない:
   - `hw_mean_next5` / `hw_mean_prev5`（同一滑走路で前後 5 機の平均ヘッドウェイ）、`hw_min_prev3`
   - `hw_prev_pairq`（先行→後続の WTC ペア別の実測最小間隔。ヘッドウェイから fit するのでラベル不要、ranking を含めて fit してよい）と `hw_excess`
   - バースト（`hw_excess ≤ 45` の連続区間）の `burst_len`、`burst_pos`、`burst_elapsed`、`burst_remaining`
   - 混合運用: 同一滑走路の直前/直後の着陸までの秒数（`arr_same_rwy_prev_s/next_s`）
   - 注意: ヘッドウェイ系は 3 時間超を欠損扱いにすべき。ranking は 1 月と 7 月が連続していないため、1 月末の便の「次の離陸」が 7 月になる（1 月最大 199 日）。既存の `rwy_headway_next_s` も同じ。
2. **nbr 群は EHAM 以外で使う、または月内で標準化してから使う**。`nbr_rg_*`（近傍の NM taxi 残差、前後 20/60 分窓）と `nbr_seq_mvt_sched_pm5` は gain 上位だが、月平均が 2025 年の範囲（EHAM 57〜160 秒）を 2026-01 で外れる（287 秒）。EHAM では 3 実験（nbr, all）で一貫して +3〜4 秒悪化。
3. **sched_backlog_60m**（予定時刻は過ぎたがまだ離陸していない便数）は NM 無しでも計算でき、NM 未マッチ行（ranking 1.5%、v2 で SSE の 58%）の混雑代理として最も素直。群としては −0.62 秒。
4. **構成は数値の要約で入れる**。`cfg_config`（出発/到着滑走路セット文字列）をカテゴリで入れると gain は大きいが汎化は弱い（§6-1 の all と all_nocfgcat の比較を参照）。代わりに「その空港の通常構成からの逸脱」（例: EDDM の到着 1 本運用フラグ、稼働到着滑走路数）を入れる方が安全。
5. やらなくてよいもの: `qhat_*`（推定オフブロック起点の待ち行列）、`cfg_since_change_bins`、`lead_wtc` 単体、時レベルの近傍平均による残差補正（§3-3 で悪化を確認）。

## 8. 注意点と限界

- 小さな LightGBM（学習行 50% 抽出、固定パラメータ）での差分であり、本番の v12/v13 系（天候特徴量や混合ヘッドを含む）に足したときの効果は小さくなりうる。特に天候（`use_weather`）は nbr 群と情報が重なる（冬の悪天候日に近傍の taxi が一斉に伸びる）。
- jan fold の学習月から jul を、jul fold の学習月から jan を除いている（ロードを軽くするため）。本番の fast CV とは学習月が 1 か月少ない。
- 2-2〜2-4 と §3〜§4 の参照値は 2025 年全体で in-sample に fit した記述統計。効果量の判断は §5（OOF 残差）と §6（月ブロック）で行うこと。
