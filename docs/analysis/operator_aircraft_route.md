# 航空会社・機材・路線・便の同一性（operator_aircraft_route）

作成 2026-09-24。対象は 2025 年学習 DEP 2,085,047 行と ranking DEP 344,841 行（ARR 行は両方とも全列）。
再現: `analysis/operator_aircraft_route_*.py`。00 → 02 → 04 → 06a → 06b の順でキャッシュ（`data/interim/oar_*.parquet`、git 管理外）を作り、
01/03/05/07/09 は 00 の後なら単独で、06c（アブレーション）→ 08 / 10 はその後に走る。
06c は `python analysis/operator_aircraft_route_06c_ablation.py base turn te te_turn rates_turn ident route all`（jan/jul）と
同じ引数に `--fwd` を付けた前方 fold。2 スレッドで 1 fold 4〜18 分（共有 CPU の混み具合次第）、常駐 2.3 GB。
外部データは OurAirports `airports.csv`（パブリックドメイン、`docs/external_data.md` 既載）を `data/external/` に置いて大圏距離に使った。

用語:
- `r` = clip(y, 0, 3600) − 空港×スタンド（03 では ×SCHED 3 時間帯）の中央値。「スタンドで説明できない」残差。
- `src` = `prc.clocks.with_clock_source`（±60 秒）の出所ラベル。
- `airline` = `CALLSIGN_flt` 先頭 3 文字、無ければ `FLIGHT_mvt` の先頭記号（ICAO 3 字 or IATA 2 字）を NM 照合行で学んだ対応表で ICAO に写したもの。
- リーク判定: 本稿の特徴量はすべて ranking の DEP 行に残る列（FLIGHT_mvt, CALLSIGN_flt, STAND_mvt, MVT/SCHED/AOBT_3 …）、
  ARR 行の BLOCK 時刻、外部の空港座標、および**学習側で fit したラベル統計の結合**だけから作る。他 DEP の BLOCK/TAXI は使わない。

## 要点

1. **スタンド再占有の下限（リークなし。`docs/analysis/stand.md` §2 と独立に同じ制約に到達 = 相互検証）**: 自機の NM オフブロック（AOBT_3）より後に同じスタンドへ別の機体がインブロックしていれば、自機はそれより前に出ている → **y ≥ MVT − そのインブロック**。
   学習 DEP の 9.18%（ranking 9.12%）に存在し、成立率 99.6%。既存の空港単位の窓カウントには無い情報。
   月ブロック検証（既存特徴量 + 待ち行列込みのレプリカに上乗せ）で **clean RMSE −3.96 秒 [−5.1, −2.8]（jan+jul）/ −2.62 秒 [−3.3, −2.0]（前方）**、該当行では −10.3 秒、10 空港中 9 空港で改善。
2. **LIRF の SCHED コピーは「便」に紐づく**: 便ごとの sched 率の分散は二項期待の 22.7 倍（他空港 2〜5 倍）、上半期→下半期の相関 0.90。sched 率 >50% の便が 45 便（ranking に 783 行）。
   (空港, FLIGHT_mvt) と (空港, 航空会社) の**出所率 TE** を分類器に入れると、レプリカで full −35.2 秒（jan+jul, CI [−81, +7]）/ **−38.7 秒（前方, CI [−79, −1.7]）**。改善は LIRF の NM 未マッチ・sched/rollover 行に集中し、尾部 40 行で大半が決まるので幅は不確実。
3. **NM 未マッチの出発便は「1 時間以上遅れた便」**（6 空港で 88〜99%、BLOCK − SCHED 中央値 78〜83 分）。ただし LIRF だけは逆で BLOCK が SCHED のコピー（中央値 5 秒）。
   ranking では EHAM・LSZH の未マッチ行の性質が変わっている（MVT − SCHED 中央値 4,471 → 6,740 / 2,094 → 5,094 秒。2025 は GA・ヘリが多かった）。
4. **LIRF 未マッチ行の FLIGHT_mvt 書式が報告系を示す**: `ITYTY680` 型（ICAO 3 字 + コールサイン末尾 5 字）は sched 73%、y 中央値 9,060 秒、2025 の rollover 15 行中 9 行。ただし群としての追加は分散で負け、情報は便キーの TE が拾う。
5. 否定的: 実航空会社名（CALLSIGN）は NM 行ではハッシュ列と 98.9% 冗長で、カテゴリとして足すと尾部で悪化（full +4.0）。便の平均タクシー時間 TE・目的地距離・ワイドボディ・折返し余裕・到着遅延の伝搬はいずれも増分なし（§9）。

**提案**: 本トピック固有の施策は **便・航空会社の出所率 TE（分類器のみ、確度中、repo v12 で −5〜−20 秒の見込み）**。スタンド再占有特徴量（確度高、−2〜−4 秒相当）は stand トピックと同一なのでそちらで一本化し、両者を同時に入れて jan+jul の対差分ブートストラップで採否を決める。§8。

## 2. NM 未マッチ行の正体と、LIRF の「便名書式」指紋

（`analysis/reporting_fingerprint_*`（別トピック）が FLIGHT_mvt 書式・NM 未マッチを扱っているので、そちらの結論と突き合わせること。本稿の数値は本稿のスクリプトによる。）

### 2-1. NM 未マッチの出発便は「大きく遅れた便」（LIRF・LTFM を除く）

| EDDF | なし | 1,956 | **4,734** | 2,632 | 0.88 | 5,759 / 5,936 |

| EHAM | なし | 4,084 | 3,747 | −122 | 0.54 | 4,471 / **6,740** |

| LTFM | なし | 3,623 | 174 | −475 | 0.17 | 1,315 / 1,196 |

- EDDF/EDDM/EGLL/LEBL/LEMD/LFPG の 6 空港では NM 未マッチ行の 88〜99% が 1 時間超の遅延便（中央値 78〜83 分遅れ）。EHAM/LSZH は 45〜54%（残りは GA・ヘリ）。NM の flight とスケジュールで照合する際、遅延が大きいと照合が外れる、と解釈できる。
  つまり **NM 未マッチ＝「本物のオフブロックが SCHED から 1〜2 時間離れている」という強い事前情報**で、`mvt_minus_sched` が大きいこと自体は `sched` コピーの証拠ではない。
- LIRF だけは BLOCK − SCHED 中央値が **5 秒**: 未マッチ行の BLOCK は SCHED のコピーが主（`sched` 45%）。同じ「未マッチ・大遅延」でも LIRF と他空港で意味が逆。
- **ranking の構成が変わっている**: EHAM と LSZH の未マッチ行は MVT − SCHED 中央値が学習 4,471 / 2,094 → ranking 6,740 / 5,094 秒。2025 の EHAM/LSZH 未マッチ行には GA・ヘリ（y≈2〜5 分、§5-3）が多く含まれたが、2026 は「遅延便型」が主。
  docs/06 §8-0 の LSZH 悪化（v5 で +52.5 秒）の一因候補: 学習側で LSZH 未マッチ行＝短タクシーの GA と学んだ分類・回帰が、2026 の遅延便型の未マッチ行に当たる。

### 2-2. LIRF の未マッチ行は FLIGHT_mvt の書式で 2 つの報告系に分かれる

`analysis/operator_aircraft_route_07_lirf_fingerprint.py`。書式 `garbled8` = `ITYTY680`, `NOSOS739`, `BAWW561D` のように
**ICAO 3 字 + コールサイン末尾 5 字**を連結した 8 字（`ITY680` → `ITY`+`TY680`）。LIRF 以外では学習に 0 行（ranking の EHAM に 7 行だけ出現）。

| LIRF 未マッチ | 学習 n | ranking n | sched% | rollover | y 中央値 | y 平均 | y>2h | MVT − SCHED 中央値 |
|---|---|---|---|---|---|---|---|---|
| `icao`（`WMT3950` 等） | 1,244 | 320 | 43.2 | 3 | 1,729 | 5,047 | 325 | 6,595 |
| `garbled8` | 164 | 40 | **73.2** | **9** | **9,060** | **17,380** | 98 | 10,113 |
| `null`（FLIGHT 欠損） | 65 | 23 | 76.9 | 0 | 1,915 | 5,524 | 9 | 2,399 |

- 2025 の rollover（24h ずれ）15 行のうち **9 行が `garbled8`**（`garbled8` 164 行の 5.5%。`icao` は 1,244 行中 3 行 = 0.24%）。LIRF 未マッチ行は全て `AIRCRAFT_TYPE_mvt` も欠損。
- NM 照合済みの `garbled8`（3,184 行）は普通の便（y 中央値 965、sched 13.8%）なので、「書式が壊れていること」ではなく「NM 未マッチ × 書式」が報告系の指紋。

**しかし、単純な事後平均ルーティングでは書式は遅延帯に勝たない**（NM 未マッチ全 22,424 行、12 か月 leave-one-month-out、`pred = p_sched·(MVT−SCHED) + (1−p_sched)·g`）:

| p_sched の群 | LIRF RMSE | LIRF 以外 RMSE | 全体 RMSE |
|---|---|---|---|
| 空港 | 7,518 | 1,149 | 2,232 |
| 空港×書式 | 6,416 | 1,141 | 1,986 |
| **空港×遅延帯（MVT−SCHED: <1h, 1-2h, 2-6h, >6h）** | **5,536** | 1,158 | **1,813** |
| 空港×書式×遅延帯 | 6,028 | 1,156 | 1,912 |
| 空港×航空会社×遅延帯 | 5,993 | 1,162 | 1,908 |

書式は単独なら効く（7,518 → 6,416）が、`garbled8` は MVT − SCHED が大きい行と重なっており、遅延帯を入れた後に足すと 1,500 行を細分しすぎて推定誤差が勝つ（+492）。
航空会社も同様（+457）。**否定的結果: LIRF 未マッチ層は 1,500 行しかなく、群の追加は分散で負ける。** GBDT の分類器に `flight_fmt` をカテゴリで渡す案は §7 で測る。

## 4. スタンドの「次の到着」がタクシー時間の下限を与える（stand.md §2 と同じ制約の独立な再現）

`analysis/operator_aircraft_route_04_turnaround.py` B2、`_09_misc.py` B、`_08_stand_bound.py`

同じ空港・同じスタンドに、自機の NM オフブロック（`AOBT_3`）より後、自機の離陸より前にインブロックした到着便があれば、
その機体が入る前に自機はスタンドを出ている。よって **BLOCK_dep ≤ inblock_next、すなわち y ≥ MVT − inblock_next**。
ARR の BLOCK と DEP の MVT/AOBT_3 は ranking に残るのでリークではない（他 DEP のラベルは使っていない）。

「離陸前で最後に同スタンドにインブロックした到着」までの間隔 `ta_gap` 別（学習）:

| ta_gap | n | **y ≥ ta_gap の成立率** | そのインブロックが AOBT_3 より後 | 同じ航空会社 | y 中央値 |
|---|---|---|---|---|---|
| ≤5 分 | 75,056 | 0.999 | 0.998 | 0.49 | 958 |

### 7-3. 何が効いているか

1. **スタンド再占有（turn）は頑健な小さい改善**: clean で −2.6〜−4.7 秒を 3 fold すべてで、CI が 0 をまたがない。効いているのは `stand_lb` のある 9.2% の行（その層の RMSE −10.3 秒）。既存の待ち行列特徴量（`q_*`）込みのベースラインに対する上乗せ。
   参考: 下限を後処理ルール `pred ← max(pred, stand_lb)` として当てるだけでは −0.07 秒（stand_lb ≤ 45 分に限定した場合。上限なしだと、stand_lb が 1 時間超の無効な下限で逆に +0.63 秒悪化、`_08_stand_bound.py`）。**特徴量として木に渡すのが正解**。
2. **便・航空会社の出所率 TE（rates / te）は尾部の分類器を鋭くする**: 改善のほぼ全てが LIRF の NM 未マッチ・`sched` / rollover 行（`EXSXS1GT`, `WMTT5232`, `ITYTY672` …の `garbled8` 便）で、`p_sched` が 0.17 → 0.69 のように上がる。
   jan+jul の SSE 変化のうち上位 20 行の改善が −38,465/行、上位 20 行の悪化が +18,496/行、残り全行で −4,161/行（`te` アーム）。すなわち **full の改善の大半は 40 行の尾部の出入りで決まり、CI が広い**。ただし前方 fold でも LIRF・NM 未マッチで CI が 0 をまたがず改善しており、方向は 3 fold で一致。
   all アームで LIRF の sched クラスの平均 `p_sched` は 0.416 → 0.429、LIRF の sched Brier は 0.0997 → 0.0980。
3. **残差 TE（`te_fl_r`, `te_al_r`）は前方では効かない**: `te` の前方 clean（LIRF 以外）は +0.47 [+0.0, +0.9] と僅かに悪化、`rates_turn`（残差 TE なし）は jan+jul の clean で `te_turn` より良い（−8.31 対 −7.30）。便の平均タクシー時間はスタンド・オペレータ・時刻で既に説明されている。**入れるのは出所率だけでよい**。
4. **ident（航空会社カテゴリ・書式カテゴリ）は単独では無価値〜有害**: gain 比率は新特徴量中最大（回帰 2.0%、分類 2.6%）だが、jul の full +7.2、NM 未マッチ +38.9 と尾部で悪化。既存の `AIRCRAFT_OPERATOR_flt` と 99% 冗長で、NM 未マッチ行でだけ新しいカテゴリ水準として過学習する。
5. **route（距離・ワイドボディ・ヘリ）は無価値**: jul clean +1.93 [+0.03, +4.05]。機種・スタンド・滑走路・目的地カテゴリで説明済み。

### 7-4. 副次的な観察

- ベースラインの OOF には負の予測が 78 行ある（最小 −3,887 秒。all アームでは −15,508 秒）。原因は候補値 `MVT − SCHED` が負の行でも `p_sched` を掛けて混合していること。repo の `prc.mixture` は最終予測を 0 でクリップしているが、**負の候補にはそもそも確率を割り振らない（genuine へ再配分）**方が筋がよい。本レプリカでは 0 クリップだけで −0.5〜−1.7 秒。
- EGLL の BAW で y>1h の genuine 行 553 行は `MVT − AOBT_3` の中央値が **602 秒**（595〜605 秒に集中）: NM が AOBT_3 を「離陸 − 既定タクシー 10 分」で逆算している印で、この場合 `AOBT_3` は時計として無意味。`mvt_minus_aobt3 ≈ 600` の尖りは既存特徴量から木が拾えるが、`aobt3` 候補の除外条件として明示する価値がある（時計担当と共有）。
