## 3. モデル

`TAXITIME = proxy + g(x)`、`proxy = MVT_TIME − AOBT_3`。決定木は恒等関係を表現できないので、この
再パラメータ化が要る。NM レコードの有無で 2 モデルに**振り分ける**（アンサンブルではない）。

| | model A | model B |
|---|---|---|
| 対象 | NM レコードあり | なし |
| 学習行 | 2,062,577 | 22,470 |
| OOF RMSE | 217.7 | 1,864.9 |
| 二乗誤差の占有 | 51.9% | 48.1% |

## 4. 誤差はどこにあるか（v8 の OOF 672,428 行）

| ラベル | 行数 | 全二乗誤差の占有 |
|---|---|---|
| y ≥ 2h | 210 | 36.7% |
| y ≥ 4h | 55 | 33.6% |
| y ≥ 約 1 日 | **10** | **24.1%** |

**10 行が指標の 4 分の 1 を決めている。** 未マッチ群の RMSE 1,864.9 は、最悪 20 行を除くと 1,044、
2,000 行を除くと **177.9**（マッチ群の 193.1 より良い）。**「未マッチが苦手」ではなく「極端行が全部」**。

算術で逆算すると、首位 245.02 に届くには未マッチ RMSE ≈ 1,033 が必要（マッチ側を現状固定）。
逆にマッチ側だけで届くには RMSE 130.8 が必要で非現実的。**マッチ側 98.8% を 10% 改善しても総合は 11 秒**。

## 5. 実験と判定

判定は `make compare A=<exp_id> B=<exp_id>`。**全行の CI が改善側 ∧ 上位 200 行を落とした後の CI も改善側**。
CV full だけで決めない（上位 20 行が 33〜46% を占めるため）。

| 比較 | 全行 | 200 行除外 | 2,000 行除外 | 判定 |
|---|---|---|---|---|
| v1 → v2（2 クロック化・木を増やす） | −4.69 | −3.33 | −2.76 | **採用** |
| v2 → v6（model B 255 葉） | −34.82 | −0.06 [−0.61,+0.52] | −0.26 | **棄却（尾部のみ）** |
| v6 → v7（model B 511 葉） | −1.03（CI が 0 跨ぎ） | −0.03 | −0.15 | 棄却 |
| v6 → v8（seed 3 本平均） | −2.66 | −1.35 | −1.08 | **採用** |

本番 LB では v3（+気象）312.02→306.29、v4（+linear_tree）306.29→305.03。**どちらも CV を取っていない。**

**v6 の「−34.8 秒」は撤回済み。** 実体は 0.26 秒で、残りは 20 行の効果だった。設定は害が無いので残している。

## 6. 分かっている穴

1. **CV と LB の対応が未検証。** 対データは v1・v2 の 2 点だけで、CV −4.7 に対し LB −33.3 と 7 倍ずれる。
   **手元の CV がどれだけ本番を予測するか分からないまま実験を積んでいる。**
2. **A/B 分割を一度もアブレーションしていない。** model B は 206 万行を捨てて 2.2 万行で学習している。
   空港・時間帯・機材の構造は NM 紐付きの有無と無関係なので、転用できるはず（未検証）。
3. **v3・v4 は CV 無しで LB 1 回だけで採用した。** 効果量が分からない。
4. 特徴量 72 列は初日のまま。一度も追加・削除の検証をしていない。

## 7. 次の一手

**最優先は 1 の穴**。v8 を 1 回提出して CV 300.22 が LB で何になるかを測る。枠の 1.5%（135 回中 1 回）。

- LB ≈ 300 → CV は信用できる。2 のアブレーション → 特徴量へ
- LB ≒ 305 以上 → **CV の尾部は本番に存在しない**。§4 の分析ごと捨てて特徴量に切り替える

**提出は依頼があるまで行わない。**

## 8. 使い方

```
make bootstrap                                  # venv + install + download + tests
make run CONFIG=configs/v8_seed_avg.yaml        # CV → ランキング予測 → 提出ゲート（アップロードはしない）
make compare A=<exp_id> B=<exp_id>              # 採用 / 棄却の判定
make test / make lint
```

`configs/` は 2 本だけ残している: `v4_linear_tree.yaml`（本番最良、気象 + linear_tree）と
`v8_seed_avg.yaml`（CV 最良）。過去の v1〜v7・v9 は git 履歴にある。
