### 判別器: 上位 200 行を除いた差が有意か

本番の答えが分かっている 2 件で検証した。

| 変更 | CV full | **200 行除外後** | 本番 LB | |
|---|---|---|---|---|
| 気象 | −3.13 [−5.23,−1.26] | **−1.06 [−1.40,−0.73]** | **−5.73** | **方向一致 ✓** |
| 気象（再測定 2026-09-25） | −1.81 [−2.76,−0.91] | **−1.26 [−1.62,−0.94]** | 未測定 | 同一 sha の on/off 対 |
| model B 255 葉 | −34.82 | **−0.06 [−0.61,+0.52]** | **+13.20** | CV full は誤り。頑健版は正しく「効果なし」 ✓ |

**200 行除外後の CI がゼロを除外する変更は、本番でも同じ方向に動く。**
**ゼロを跨ぐ変更は、CV full が何秒を示そうと尾部のまぐれで、本番には転移しない。**

**訂正（2026-09-17）**: 上表の `model B 255 葉` の行（−34.82 / −0.06 [−0.61,+0.52] / −0.26）は
**`experiments/` のどの組でも再現しない**。v2 当時の OOF ファイルがリポジトリに残っていないため。同じ設定変更
（model B 127/50 → 255/20）の実測は main-ab56551b5e → main-f9d57a661f の **−36.60 / −0.36 [−0.89,+0.18] /
−0.25** と det_a → ab_split の **−34.58 / −0.27 [−0.85,+0.31] / −0.24**（`docs/investigation_2026-09-16/results/decision-rule-blind-to-tail.md` §3.6）。
数値は近いが同一ではない。さらに「既知 2 事例で本番 LB と方向が一致した」という主張自体は、当該提出の LB 結果を
突き合わせないと検証できず、調査では **UNDETERMINED** として残っている（同 §4, §5）。この節の見出し
「条件付きでできる」は、**2 事例での検証というより、まだ確かめていない仮説**として読むこと。

理由: 67 万行のうち 10 行が二乗誤差の 24% を占め、その 10 行は CV（2025 年）と本番（2026 年）で
別の行。尾部に載った効果は互いに独立したくじ引きになる。一方、広く効く変更は両方に載る。

### 使い方

```
make compare A=<exp_id> B=<exp_id>      # 4 段（0/20/200/2000 行除外）＋群別を出す
```

- **採否は 200 行除外後の CI で決める。** CV full は参考値
  - **訂正（2026-09-17）**: コードはそう動いていない。`verdict()` は **全行の CI を先に読み、そこがゼロを
    跨げば 200 行除外後を見ずに REJECT** する。実際の規則は「**全行の CI と 200 行除外後の CI の両方が
    改善側のときだけ ADOPT**」。例: det_a → main-48c19bc830（シード 1→3 本）は 200 行除外後が
    −2.58 [−2.96,−2.15] でも全行が [−3.75,+0.55] なので REJECT になる
    （`docs/investigation_2026-09-16/results/decision-rule-blind-to-tail.md` §3.1, §4）
- **方向は信用できるが、大きさは信用できない。** 気象は CV −3.13 に対し本番 −5.73（1.8 倍）
- **未マッチ行だけを動かす変更は測れない**（対比較でも CI 幅 62 秒）。**触らない**
  - **訂正（2026-09-17）**: 62 秒という幅は **手元のどの組でも再現しない**（どの組を測った値なのかも
    本書・handoff のどちらにも書かれていない）。実測の未マッチ行だけの対比較 CI 幅は
    **385.0 秒**（det_a → ab_split）/ **724.4**（ab_single → ab_split）/ **421.5**
    （main-ab56551b5e → main-f9d57a661f）、forward のみの組で **5.57**、model B の予測が同一の組で
    **0.00**。マッチ行側も 0.77 秒ではなく **0.14〜1.17 秒**（`docs/investigation_2026-09-16/results/decision-rule-blind-to-tail.md` §3.3）。
    幅は「62 秒」という 1 つの定数ではなく比べる組で 2 桁動くので、**「測れないから触らない」という
    結論はその前提ごと失効している**（§10 の Phase 2 再開理由も参照）

### どの fold を判定に使うか → **forward のみ**

本番は 12 か月すべてで学習して 2026 年を予測する。fold がその形に近いかで選ぶ。

| fold | 前向きか | 学習量 | 判定に使うか |
|---|---|---|---|
| jan | ✗ 2〜12月で学習して 1月を当てる | 11か月 | 使わない（季節の様子見のみ） |
| jul | ✗ 同上 | 11か月 | 同上 |
| jul_fwd | ✓ | 6か月（少なすぎ） | 使わない |
| **forward** | **✓ 1〜10月で学習して 11〜12月** | **10か月** | **これを使う** |

`jul` 375.01 に対し `jul_fwd` 421.69 と 46.7 秒悪いが、**この差は「リークが消えた」と
「学習データが 11→6 か月に半減した」の両方を含み、分離できていない**（対照群を設計し損ねた）。
分離しても結論は変わらないので追わない。**forward が唯一「前向き」と「十分な学習量」を両立する。**

スクリーニングは `folds: [forward]` ＋ `--skip-predict` で約 5 分。

**訂正（2026-09-17）**: この 4 fold のうち **`jul_fwd` は `overall` に 1 行も入っていない**。`run_cv` は
fold 順 `[jan, jul, jul_fwd, forward]` で `pl.coalesce` するが、`jul` と `jul_fwd` は同じ 190,713 行を
予測するので先に書いた `jul` が残る。結果として **`overall.n` は 672,428、fold の行数合計は 863,141** で、
4 fold の記録 6 件すべてで `overall.rmse_full` が pooled{jan, jul, forward} に 3 桁一致し、
pooled{jan, jul_fwd, forward} とは 7.6〜14.0 秒ずれる（`docs/investigation_2026-09-16/results/fold-shape-vs-ranking.md` §3.3）。
プーリングの中身は変えていない（既存のログの数字はそのまま読める）が、2026-09-17 に記録側を直し、
`overall.folds_pooled` / `overall.folds_shadowed` と fold ごとの `n_into_overall` を出すようにした。
**`overall` は「{jan, jul, forward} をプールした OOF」と読むこと。**

### 8.1 v6〜v8 の後退の根本原因（2026-09-16、**推測ではなく実測**）

| 提出 | LB | 内容 |
|---|---|---|
| v4 | **305.03** | 現最良（旧コード、気象 + linear_tree） |
| v8 | 343.80 | v2 相当の設定を現行コードで再現 |
| v9 | **306.46** | v8 のマッチ行 ＋ v4 の未マッチ行（probe） |

v9 = 306.46 は v4 の 1.4 秒差。**37.3 秒の差は丸ごと未マッチ 5,290 行（1.53%）から来ている。**
リファクタもマッチ行のモデルも無罪。

事故の中身は 2 件で、どちらも私（Claude）の過失:
1. **v6 = 350.62**: `configs/main.yaml` に `exclude_features` が無く、棄却済みの候補 9 列が全部本番に入った。
   うち `noise_control` は「信号を持たないこと」を目的に作ったハッシュ列。→ 候補列を opt-in
   (`include_candidates`) に反転し、テストで固定。
2. **model B の抽選性**: 学習 22,470 行に極端例が 33 個しかなく、early stopping のホールドアウト
   (~1,650 行) に 0〜5 個しか入らない。`rounds_unmatched` が 199 / 212 / 585 / 658 と乱高下し、
   2026 年のどの行に極端な予測が当たるかが**運**になる。その振れ幅が ±37 秒。

## 9. 分かっている穴

1. **fold の構造が本番と違う。** ランキングは 2026 年 1 月・7 月なのに、CV の jan fold は
   2025 年 2〜12 月で学習して 2025 年 1 月を当てている（未来で過去を当てている）。本番と同じ形
   （過去だけで先を当てる）なのは forward fold だけ。スクリーニングは `folds: [forward]` で回す。
2. **v3・v4 は CV 無しで LB 1 回だけで採用した。** 効果量が分からない。
3. 特徴量 72 列は初日のまま。§6 でブロック単位の必要性は確認したが、**1 列ごとの検証はしていない**。
   - **訂正（2026-09-17）**: 「72 列（うちエンコーディング 9 列）」は列の数え方が違っていた。72 =
     **フレームの数値列 71 + `month`** であり、**エンコーディング 9 列を含まない**（9 列は
     `predict_fold` の中でフレーム構築後に結合される）。しかも `month` は毎コミットで落とされている。
     LightGBM が実際に見た行列は model A で **80+10**（v1/v2/v5/v8）/ 97+10（v3/v4）/ 107+10（v6）/
     **98+10**（v7 と現行）、model B で 65 / 82 / 92 / 83 + 10 — 各コミットのコードを実行して再導出した
     （`docs/investigation_2026-09-16/results/n-features-72-mislabel.md` §3.1, §3.2）。
     「初日から変更なし」も誤り（列数は v1 → 現行で 80 → 98 に動いている）。1 列ごとの検証が無いのは事実。
4. **依存の固定が無い**（`uv.lock` 無し、全部 `>=`）。終盤に再現性が壊れると致命的。
5. **未使用列が残っている**: `CALLSIGN_flt` / `ADES_FILED_flt` / `ARVT_3_flt`。

### Phase 2' の候補（3 本、いずれも未測定）

| | 施策 | 根拠 |
|---|---|---|
| a | **`shared_b`**: model B を全 208 万行で学習（スケジュール系の特徴量のみ使用） | 極端例が 33 個 → ~2,000 個になる。**実装したが一度も測っていない** |
| b | **model B のシードを 10〜20 本平均** | ±37 秒の抽選（§8.1-2）を平均で潰す |
| c | **early stopping を廃止し木の本数を固定** | `rounds_unmatched` 乱高下の発生源そのもの |

**訂正（2026-09-17）**: 3 本とも「根拠」の側が実測で崩れた。施策そのものの是非は下記のとおり。

- **a の根拠は否定**: 206 万のマッチ行をプールしても極端例は **33 → 34**（y ≥ 12h）、119 → **122**
  （y ≥ 4h）、481 → **584**（y ≥ 2h）。33 行が ~2,000 行になるような閾値は存在しない
  （`docs/investigation_2026-09-16/results/shared-b-no-transfer.md` §H）。施策自体は forward fold で **実測済み**になり、
  未マッチ OOF **2,109.32 → 2,144.73**、fold 全体 284.70 → **287.12**、`prc.compare` は **REJECT**
  （全行 +2.41 [−20.40,+20.49]）。ただし内訳は割れていて、**非 LIRF の未マッチは 1,034.74 → 486.57**
  と半減し 10 空港中 9 空港で改善する一方、**LIRF は 8,578 → 9,690 と悪化**する
  （`docs/investigation_2026-09-16/results/shared-b-all-rows.md` §3.1〜§3.3）。
- **b の根拠は失効**（±37 秒 = 本数の抽選、が §8.1-2 のとおり否定された）。施策自体も実測済みで、
  model B のシード平均は未マッチ OOF **3 シード 2,312.5 / 1 シード 2,299.0** と効かない
  （`docs/investigation_2026-09-16/plan.md` §2 `seed-avg-no-effect-b`）。
- **c は設定では実行不可能**: `unmatched_num_rounds` は `min(...)` の中の**上限**であって本数指定ではなく、
  `unmatched_num_rounds: 600` はビット同一の実行になった（`make compare` が 4 段すべて
  `+0.00 [+0.00,+0.00]`）。`inner_holdout_months` / `early_stopping` は model A と共有なので、
  切れば A の early stopping も消える。本数を固定するにはコード変更が要る
  （`docs/investigation_2026-09-16/results/holdout-month-decides-rounds.md` §2, §4.2, §5）。

進め方: CV で「悪化していないこと」だけ確認 → probe 提出（v4 のマッチ行 ＋ 候補の未マッチ行）で厳密に測る。

## 11. 使い方

```
make bootstrap                                  # venv + install + download + tests
```
