# 外部特徴量: 気象の修理と Open-Meteo の降水・降雪 — 事前登録（2026-09-25）

計画 P8（`docs/competitor_research_2026-09-21/plans/P8-weather-and-coverage-gate.md`）の P8-B と P8-C を実行する。
結果を見る前に書く。判定規則・群・列の定義は測定を始めた後に変えない。

## 0. 動機（実測）

- IEM は米国外の空港に降水量を配信しない（IEM のダウンロードページに明記）。そのため本番の気象列のうち
  `precip_mm`, `precip_mm_prev1h`, `temp_x_precip`, `temp_x_precip_prev1h` の 4 列は全行ゼロ（P8 §0）。
- 防除氷ゲート `deicing_gate = (temp ≤ 3 °C) ∧ (precip_mm > 0 ∨ 凍結性の天気コード)` の降水の項は発火しない。
  0 °C 前後の雨・霧雨は拾えていない。
- `frozen_wx` は Boolean 型のため `numeric_feature_columns` に入らず、モデルに渡っていない。
- 2026 年 1 月は防除氷ゲートの時間が 2025 年 1 月の 2.70 倍（`16-external-data.md` §7）で、採点行の 44 % を占める。
  Open-Meteo の降雪時間も EDDF で 2026-01 / 2025-01 = 3.9 倍（P8 §4.1）。
- ライセンス: IEM はパブリックドメイン、Open-Meteo のデータは CC BY 4.0。どちらも賞の条件
  （「追加データはオープンソースライセンスで公開されていること」）を満たす（`16-external-data.md` §6.4–6.5）。

## 1. 候補の列（離陸時刻の 1 時間枠。1 時間前のコピーは作らない）

### B: METAR の天気コードから（追加ダウンロードなし）

| 列 | 定義（その時間帯の METAR のいずれかで） |
|---|---|
| `wxv2_wet` | 天気コードに `RA` または `DZ`（雨・霧雨。-RA/+RA/SHRA/TSRA/FZRA などを部分一致で含む） |
| `wxv2_shower` | `SH` または `TS`（しゅう雨・雷雨） |
| `wxv2_obscure` | `FG`, `BR`, `HZ`, `FU` のいずれか（霧・もや・煙霧） |
| `wxv2_frozen` | 既存の凍結性コード（`SN, SG, PL, IC, GS, GR, FZ`）。既存の `frozen_wx` の Int8 版 |
| `wxv2_deicing_gate` | `(temp_c ≤ 3) ∧ (wxv2_frozen ∨ wxv2_wet)` |

### C: B ＋ Open-Meteo（`models=ecmwf_ifs`、空港座標は OurAirports のキャッシュ、1 空港 1 リクエスト）

| 列 | 定義 |
|---|---|
| `om_precip_mm` | その時間の降水量（mm、Open-Meteo の時刻ラベルの時間） |
| `om_snowfall_cm` | その時間の降雪量（cm） |
| `om_snow_depth_m` | 積雪深（m） |

Open-Meteo の気温・風・視程は取り込まない（空港の実測である METAR の方が良い、P8 §4.2）。

実装は `src/prc/weather.py`（表の構築）と `src/prc/train.py`（fold 内で離陸時刻の時間に結合、フラグで切替）。
**特徴量キャッシュは変更しない**ので、base 群は本番（`main_gap`、v14）と同一。

## 2. 群と判定

測定条件: `configs/main_gap.yaml` ＋ `folds: [jan, forward]`（冬を含む 2 fold をまとめて 1 つの OOF にする。
防除氷の効果は冬にしか出ないので jan fold を必ず含める）。

| 群 | 変更 | 追加 / 除外 |
|---|---|---|
| base | なし | — |
| noise5 | 常にゼロの 4 列を除外 ＋ ハッシュ列 5 本 | +5 / −4 |
| B | 常にゼロの 4 列を除外 ＋ B の 5 列 | +5 / −4 |
| noise8 | 常にゼロの 4 列を除外 ＋ ハッシュ列 8 本 | +8 / −4 |
| C | 常にゼロの 4 列を除外 ＋ B の 5 列 ＋ Open-Meteo の 3 列 | +8 / −4 |

**合格** = 次の 2 つを両方満たす（前回の記事の検証と同じ規則）。

1. `prc.compare base <候補>` が **ADOPT**（全行と K=200 の 95 % CI がともに改善側でゼロを除外）。
2. `prc.compare <対応するノイズ群> <候補>` の **K=200 の 95 % CI が改善側でゼロを除外**。

C は B との比較も記録する（`prc.compare B C`）。C が合格しても B に勝たないなら、推奨は B。

**補足の読み方（判定には使わない）**: fold 別・月別・空港別の差、防除氷ゲートが立つ行だけの差を併記する。
本番の 2026 年 1 月は冬の条件が 2025 年より大幅に多いので、CV の差は本番の差より小さく出ると予想する。
この予想で判定を甘くすることはしない。

## 3. パリティ（P8-D の考え方）

新しい列それぞれについて、学習側（2025）と 2026 年 1 月・7 月のランキング行で、欠損率と非ゼロ率を並べる。
学習で密・本番で空、またはその逆の列があれば、その列は判定にかかわらず使わない。

## 4. 範囲

本番（`configs/main_gap.yaml`）と提出は変えない。結果と推奨を記録し、判断はユーザーに委ねる。

## 5. 追記（測定開始前、パリティ規則 §3 の適用）

Open-Meteo を取得した時点で、`om_snow_depth_m` が 2025 年の大半で欠損していることが分かった（2025-01 77 %、
2025-06〜07 100 %、2025-12 以降 0 %。10 空港すべて同じ 6,443 時間）。学習でほぼ空・本番で全行に値がある列なので、
§3 の規則どおり**判定の前に除外する**。これに伴い C は B の 5 列 ＋ Open-Meteo 2 列（`om_precip_mm`,
`om_snowfall_cm`）の 7 列になり、対照は noise8 ではなく **noise7** にする。規則の適用であって、結果を見た変更ではない
（どの群もまだ走らせていない）。
