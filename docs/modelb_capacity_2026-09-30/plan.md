# model B の容量は本当に見込みがないのか — 再調査の事前登録（2026-09-30）

## 0. 過去の結果と、再調査する理由

| 変更（当時のレシピ） | CV | LB | 当時の結論 |
|---|---|---|---|
| model B 255 葉 / min_data 20（v5、2026-09-14） | −34.8 s（200 行除外で −0.06） | **+13.2 s**（312.02 → 325.22） | 尾部の数十行を葉に切り出し、2026 年の似た行に誤発火。12 h 超の予測が学習データの 2 倍の頻度 |

**再調査の理由**: どちらの測定も、その後に入った 2 つの変更の前のレシピだった。

1. LIRF の未マッチ行で目的変数を `mvt_minus_sched` だけずらす再パラメータ化（v10 以降）。尾部の大半（LIRF の予定時刻流用）が
   木の恒等写像の問題として解かれ、葉で尾部を切り出す必要が減っている。
2. flseq 特徴量（v16）。便名の形式・重複記録の列が、未マッチ行の構造を別の形で説明している。

容量を上げたときの失敗の機構（尾部の孤立）が今のレシピでも起きるかは、測らないと分からない。

## 1. 群（本番レシピ `configs/main_flseq.yaml` ＋ 4 fold。model B の設定だけを変える）

| 群 | model B |
|---|---|
| base | 127 葉 / min_data 50（本番） |
| B255 | 255 葉 / min_data 20（v5 の設定） |
| B5 | 127 葉 / min_data 5（item 10 の設定） |
| mix255 | 予測を base と B255 の平均にする（事前に決めた固定の重み 0.5） |
| mix5 | 予測を base と B5 の平均にする（固定の重み 0.5） |

**測り方**: model B は model A と独立に学習される（`predict_fold` で別々の `_fit`）。そこで各群は model A の学習を
10 ラウンドに縮めた設定で走らせ、マッチ行の予測は base の OOF をそのまま差し込む（未マッチ行だけが群ごとに違う）。
**検証**: 本番と同じ model B の設定でこの方法を走らせたとき、未マッチ行の予測が base と一致すること。一致しなければ測定しない。

## 2. 判定

**LB で確かめる価値あり（ユーザーに提出の判断を仰ぐ）** = 次の 3 つをすべて満たす。

1. `prc.compare base <群>` が ADOPT（全行と K=200 の 95 % CI がともに改善側でゼロを除外）。
2. **記録の壊れを除いた未マッチ行**でも改善する: 未マッチ行のうち、ラベルが 1 日ずれの帯（|y − 86,400| < 5,400）と
   ラベル > 12 h を除いた行で、行単位 bootstrap の差の 95 % CI が改善側でゼロを除外する。
   （除外はラベルを見るので評価専用。予測には使わない。）
3. **2026 年で過信しない**: 本番と同じ学習（全 12 か月）でランキングの未マッチ行を予測したとき、12 h 超の予測の割合が、
   学習データのラベルで 12 h を超える割合の 1.5 倍以下。

どれかを満たさなければ「見込みなし（今のレシピでも）」と記録する。満たした場合も提出はユーザーの判断。
