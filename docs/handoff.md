## 3. 現在のゴール

> **model B（未マッチ 5,290 行）の RMSE を 1,736 から 1,300 以下に下げる。**
> 達成できれば総合 305 → 270。930 まで行けば 245（首位相当）。

### 候補 3 本（いずれも未測定）

| | 施策 | 根拠 |
|---|---|---|
| **a** | **`shared_b`**: model B を全 208 万行で学習（スケジュール系の特徴量のみ使用） | 今の model B は学習 22,470 行・極端例 33 個だけ。これが ~2,000 個になる。**実装したが一度も測っていない** |
| **b** | **model B のシードを 10〜20 本平均** | `rounds_unmatched` が 199 / 212 / 585 / 658 と乱高下し、2026 年のどの行に極端な予測が当たるかが運になっている。振れ幅 ±37 秒 |
| **c** | **early stopping を廃止し木の本数を固定** | 上記乱高下の発生源そのもの。ホールドアウト ~1,650 行に極端例が 0〜5 個しか入らず、判断材料が足りていない |

### 測定方法（ここが肝）

- **CV では model B を判定できない**（この行グループの対比較は CI 幅 62 秒。どんな改善も埋もれる）
- **probe 提出なら厳密に測れる**。v9 がそれを実証した:
  **「v4 のマッチ行を固定し、未マッチ行だけ候補モデルに差し替えて提出する」**
  → LB の差分がそのまま model B の差分になる（交絡なし）
- 残り 25 日 × 1 日 5 枠 ≒ **125 枠**。これを probe に使える

## 4. 引き継ぎ前に踏んだ地雷（同じ穴に落ちないために）

1. **v6 = 350.62 の事故**: 棄却済みの候補列 9 本（信号を持たないハッシュ列 `noise_control` を含む）が
   設定ミスで本番に入った。→ 候補列は **opt-in**（`include_candidates`）に反転済み、テストで固定。
2. **`feature_fraction: 0.8` は列を 1 本足すと全部の木の抽選が変わる。** 「特徴量の効果」ではなく
   「モデルの引き直し」を測ってしまう。→ スクリーニングは **`ff=1.0` ＋ノイズ対照列**で行う。
3. **`deterministic: True` は `force_row_wise` が無いと効かない。** 同一設定で木の本数が 33% 振れていた。
4. **気象の結合が特徴量 `hour_utc` を上書き削除していた**（v3・v4 はこの状態で学習されている）。修正済み。
5. **CV full（全行 RMSE）で判定してはいけない。** 上位 20 行が二乗誤差の 33〜46% を占める。
   判定規則は「**全行の CI が改善側 ∧ 上位 200 行を落とした後の CI も改善側**」（README §6）。
   これを無視して CV を信じた v5 は、本番で +13.2 秒後退した。
6. **fold は `forward` のみを判定に使う**（他の fold は未来で過去を当てていて、本番と形が違う）。
7. **推測と実測を混ぜない。** 「たぶんこれが原因」で止めず、probe/アブレーションで切り分ける。

### 未処理の宿題

- 依存の固定が無い（`uv.lock` 無し、全部 `>=`）。終盤に再現性が壊れると致命的
- 未使用列 `CALLSIGN_flt` / `ADES_FILED_flt` / `ARVT_3_flt`
- `planned_flight_s` が唯一の惜しい候補（−0.21 [−0.49,+0.08]、マッチ行 218.5→218.1）。再検討の余地あり

### 運用の制約

- **提出は本人の依頼があるまで行わない**（1 日 5 枠、9-15 は 4 枠使用済み）
- **最終評価は隠しセットの可能性が高い。** public LB の上位 20 行に合わせ込む改善は転移しない。
  原理的に正しい変更（学習データを増やす、シードを平均する）を優先する
- モデル凍結 10-09、内部締切 10-11 12:00Z（JST 21:00）、最終日は 5 枠中 2 枠を予備に残す

## 5. ChatGPT に貼るプロンプト

以下をそのまま貼る。リポジトリを渡せる場合は `docs/README.md` も一緒に添付する。

````text
あなたは Kaggle 型コンペの共同作業者です。以下のコンペで、私と一緒に精度を上げてください。

# コンペ
- PRC Data Challenge 2026。出発便の taxi-out 時間（秒）を予測。評価は RMSE。欧州 10 空港。
- 締切 2026-10-11。提出は 1 日 5 回まで。最終評価は隠しセットの可能性が高い
  （過去回は締切直前に新しい便を追加投入した実績あり）。
- 私のチーム: resilient-hedgehog。現在の最良提出 305.03、53/127 位。首位 245.02、2 位 249.20。

# 今のモデル
- TAXITIME = proxy + g(x)、proxy = MVT_TIME − AOBT_3（決定木は恒等関係を表現できないため、
  この再パラメータ化が必要）。LightGBM。
- NM（Network Manager）レコードとマッチするかどうかで 2 モデルに「振り分け」ている（アンサンブルではない）:
  - model A = マッチ行、学習 2,062,577 行、OOF RMSE 217.7
  - model B = 未マッチ行、学習 22,470 行、OOF RMSE 1,864.9
- 全体の二乗誤差の 48% が model B（行数では 1.53%）に集中している。

# 実測で分かっていること（推測ではない）
1. 誤差は極端な少数行に支配されている。OOF 672,428 行のうち、上位 10 行が全二乗誤差の 24.1%、
   上位 210 行（y≥2h）が 36.7% を占める。
2. probe 提出（マッチ行を最良モデルで固定し、未マッチ行だけ差し替える）で切り分けた結果、
   直近の 37 秒の後退は「丸ごと未マッチ 5,290 行」が原因だった。マッチ行側は無罪。
3. LB スコアから逆算すると、model B の RMSE は 我々 ≈1,736 / 首位 ≈929。
   マッチ行（98.5%）は既に首位と互角で、60 秒の差はすべて 1.53% の行にある。
4. マッチ行向けの特徴量を 4 つの仮説ファミリーで 10 本試して、全部棄却された（この空間は飽和）。
5. model B は学習 22,470 行に極端例が 33 個しかなく、early stopping のホールドアウト（~1,650 行）に
   0〜5 個しか入らない。木の本数が 199/212/585/658 と乱高下し、2026 年のどの行に極端な予測が当たるかが
   運になっている。振れ幅は総合スコアで ±37 秒。
6. CV では model B を判定できない（この行グループの対比較は 95%CI 幅が 62 秒）。
   一方 probe 提出なら厳密に測れる（LB の差分＝model B の差分）。残り枠は約 125。

# 採否の判定規則（これは必ず守ってください）
- CV の全行 RMSE だけで判断しない。上位 20 行が二乗誤差の 33〜46% を占めるため、
  全行 RMSE は尾部の当たり外れを測っているだけになる。
- 判定は対ブートストラップで「全行の 95%CI が改善側」かつ「上位 200 行を除いた後の 95%CI も改善側」。
  この規則は既知 2 事例で本番 LB と一致することを検証済み。
- 検証 fold は「過去だけで未来を当てる」形（forward）のみを使う。

# 今のゴール
model B（未マッチ 5,290 行）の RMSE を 1,736 → 1,300 以下に下げる（総合 305 → 270 相当）。
候補は 3 本、いずれも未測定:
  a. model B を全 208 万行で学習する（スケジュール系の特徴量のみ使用）。極端例が 33 → 約 2,000 になる
  b. model B のシードを 10〜20 本平均して、上記の「抽選」を平均で潰す
  c. early stopping を廃止して木の本数を固定する（乱高下の発生源）

# あなたへの依頼
上記 a/b/c の優先順位と、それぞれの具体的な実装方針・想定リスクを述べてください。
さらに、私が見落としている第 4 の選択肢があれば挙げてください。
特に「学習行が 2 万行で、うち極端例が数十個しかない小さな回帰モデルの分散を減らす」一般的な手法
（分位点回帰 / 対数変換 / Huber / Tweedie / 2 段階分類＋回帰 / 極端行の別扱い など）について、
この問題設定で有効そうなものを、根拠とともに教えてください。

# 進め方のルール
- 推測と実測を明確に分けて書いてください。「たぶん効く」は「未検証」と明示すること。
- 一度に 1 つの変更だけを提案し、それをどう測るか（CV か probe 提出か）も一緒に書いてください。
- public LB の上位 20 行に合わせ込む改善は隠し最終評価で消えるので、原理的に正しい変更を優先してください。
- 回答は簡潔に。冗長な前置きは不要です。
````
