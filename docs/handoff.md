## 5. CV の測定値

### 判定規則（`make compare`）

対ブートストラップで「全行の 95% CI」と「上位 200 行を除いた後の 95% CI」の両方を見る。
既知 2 事例（気象、model B 255 葉）で本番 LB と一致した。
未マッチ行だけの対比較は 95% CI 幅が 62 秒。マッチ行は 0.77 秒。

fold は `jan` / `jul` / `jul_fwd` / `forward` の 4 種。`forward` 以外は未来のデータで過去を当てている。

**訂正（2026-09-17、実測）**

- **CI 幅 62 秒 / 0.77 秒はどの組でも再現しない**。未マッチ行だけの対比較の幅は **385.0**
  （det_a → ab_split）/ **724.4**（ab_single → ab_split）/ **421.5**
  （main-ab56551b5e → main-f9d57a661f）/ **5.57**（forward のみの組）/ **0.00**
  （model B の予測が同一の組）。マッチ行は **0.14〜1.17**。62 秒 / 0.77 秒を出した組は本ファイルに
  書かれておらず、特定できていない（`docs/investigation_2026-09-16/results/decision-rule-blind-to-tail.md` §3.3）
- **規則の実装は「200 行除外後で決める」ではない**: `verdict()` は全行の CI を先に読み、そこがゼロを
  跨げば 200 行除外後を見ずに REJECT する。コード上の規則は「全行の CI と 200 行除外後の CI の両方が
  改善側のときだけ ADOPT」（`docs/investigation_2026-09-16/results/decision-rule-blind-to-tail.md` §3.1, §4）
- **「既知 2 事例で本番 LB と一致」は未確定**。該当する `v2 → v6` の CV 値（−34.82 / −0.06 / −0.26）は
  v2 当時の OOF ファイルが `experiments/` に無いため再現できず、最も近い実測は
  −36.60 / −0.36 [−0.89,+0.18] / −0.25 と −34.58 / −0.27 [−0.85,+0.31] / −0.24。調査は
  UNDETERMINED として記録している（同 §3.6, §4, §5）
- **`overall` は 4 fold のうち 3 つしか含んでいない**: fold 順 `[jan, jul, jul_fwd, forward]` の
  `pl.coalesce` で、`jul` と同じ 190,713 行を予測する `jul_fwd` は 1 行も入らない。`overall.n` =
  **672,428** に対し fold の行数合計は **863,141**（`docs/investigation_2026-09-16/results/fold-shape-vs-ranking.md` §3.3）。
  2026-09-17 にプーリングはそのままで記録側を修正し、`overall.folds_pooled` /
  `overall.folds_shadowed` と fold ごとの `n_into_overall` を残すようにした
- **fold の形**: 学習月数は 11 / 11 / 6 / 10、前向き horizon は最大 2 か月（本番は 1 か月と 7 か月）、
  年をまたぐ fold は無く、1 月を予測する前向き fold も無い（同 §3.1, §3.2）

## 6. model B の挙動（実測）

- 学習 22,470 行のうち、極端値（y ≥ 4h 相当）は 33 行
  - **訂正（2026-09-17、実測）**: **33 は y ≥ 12h（43,200 秒）の行数**。y ≥ 4h は **119 行**、
    y ≥ 2h は **481 行**、y ≥ 80,000 は 15 行。なお y ≥ 43,200 の学習行 34 のうち日またぎ帯

- early stopping 用ホールドアウトは約 1,650 行。そこに含まれる極端値は 0〜5 行
  - **訂正（2026-09-17、実測）**: 12 月ホールドアウトは **1,649 行**で y ≥ 14,400 が **6 行**
    （行数は再現済み、6 は未再測定）。forward fold が使う 10 月ホールドアウトは **1,913 行**、
    y ≥ 4h **4 行**、y ≥ 12h **0 行**、最大 y **25,558**
    （`docs/investigation_2026-09-16/results/holdout-month-decides-rounds.md` §4.1）

    (ii) 本数はホールドアウト月で決まり、`inner_holdout_months` 1 → 2 で **45 → 413**

## 7. 修正したバグ（すべて再現確認済み）

1. **v6**: `configs/main.yaml` に `exclude_features` が無く、棄却済み候補 9 列（うち `noise_control` は
   信号を持たないハッシュ列）が本番モデルに入った。→ 候補列を opt-in（`include_candidates`）に反転、テスト追加
2. **`feature_fraction: 0.8`**: 列を 1 本足すと全ての木で列抽出が変わる。信号ゼロの `noise_control` を
   足したときのコストが +0.53 で、実特徴量 3 本（+0.49 / +0.39 / +0.50）と同じだった。
   → スクリーニングは `feature_fraction: 1.0` ＋ノイズ対照列で実施
3. **`deterministic: True`**: `force_row_wise` が無いと効かない。同一設定で木の本数が 959 / 1273 と振れていた。
   → 修正後の残差ドリフト 0.023 秒
4. **気象の結合**: 結合キー名が特徴量 `hour_utc` と衝突し、上書き後に削除していた。
   → `WX_KEY = "_wx_hour"` に改名。**v3 と v4 はこのバグがある状態で学習されている**
5. **気象の結合（タイムゾーン）**: 公式 parquet は UTC aware、METAR は naive でクラッシュしていた
6. **`prc.compare` の判定文言**: `[+18.44, +53.51]` を「CI がゼロを含む」と表示していた
7. **提出回数カウンタ**: ログ行数（1 提出につき 2 行）を数えていて、4 回目の提出を 6/5 として拒否した
8. **`feature_parity_report` と `predict_fold` の列可視性の実装が二重化**していた
   → `visible_numeric_columns()` に一本化

# 作業中に見つけて修正したバグ
1. 棄却済みの候補列 9 列（うち 1 列は信号を持たないハッシュ列）が設定ミスで本番モデルに入った（v6）。
2. feature_fraction 0.8 のため、列を 1 本足すと全ての木で列抽出が変わる。信号ゼロの対照列を足した
   ときのコスト +0.53 が、実特徴量 3 本（+0.49 / +0.39 / +0.50）と同じだった。
   以後スクリーニングは feature_fraction 1.0 ＋ノイズ対照列で実施。
3. deterministic: True が force_row_wise 無しでは効かず、同一設定で木の本数が 959 / 1273 と振れていた。
4. 気象データの結合キー名が特徴量 hour_utc と衝突し、その列を上書き後に削除していた。
   v3 と v4 はこのバグがある状態で学習されている。
5. 気象結合のタイムゾーン不一致（UTC aware と naive）。
6. 比較ツールが [+18.44, +53.51] を「CI がゼロを含む」と表示していた。
7. 提出回数カウンタがログ行数（1 提出 2 行）を数え、4 回目の提出を 6/5 として拒否した。
