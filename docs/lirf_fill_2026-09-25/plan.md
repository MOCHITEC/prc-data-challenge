## 0. 動機（すべて実測、`afe_forward_base-27b685dad7` の forward OOF）

`BLOCK_TIME` が `SCHED_TIME` と 10 秒以内で一致する行（= 空港の報告系が実測の off-block ではなく予定時刻を
書いた行、以下「流用行」）を、マッチ行（NM レコードあり）について空港別に数えた。

| | LIRF | 他の 9 空港 |
|---|---|---|
| 流用率 | **19.96 %**（23,256 行中） | 1.19〜5.62 % |
| 空港内の二乗誤差に占める流用行 | **41.3 %** | 0.9〜11.2 % |
| モデルの RMSE（流用行 / それ以外） | **431.9 / 257.4** | 流用行の方が良いか同程度（LEBL を除く） |

オラクル（流用行を完全に知って `MVT − SCHED` を返す）なら、LIRF マッチ行 300.4 → 230.2、マッチ行全体
198.53 → 188.63。`results/model-a-ceiling.md` が「回収可能」とした誤差の 35 % が LIRF に集中していることと整合する。

未マッチ行向けの同種の分類器（P1 stage 2）は AUC 0.9201 で、事前のゲート 0.93 に届かず閉じた。ただし
マッチ行の方が学習行が約 100 倍多く（LIRF マッチ 約 16 万行 vs 未マッチ 1,488 行）、NM の時刻列も使える。
**マッチ行では未測定**なので測る。

## 1. 事前テスト（オフライン、読み取りのみ）

本実装の前に、既存の base OOF に後から混ぜるだけの安い測定で、見込みがあるかを判定する。

- **分類器**: LightGBM 二値分類。対象は LIRF のマッチ行。ラベル `fill = |BLOCK − SCHED| ≤ 10 s`（学習行でのみ観測可能）。
  入力は特徴量キャッシュの数値列（`numeric_feature_columns`。BLOCK_TIME / TAXITIME 由来の列は構造的に含まれない）＋
  既存のカテゴリ列＋ `flight_prefix`（`FLIGHT_mvt` の先頭 3 文字）＋ `flight_identity`（`FLIGHT_mvt` 全体）。
  63 葉、学習率 0.05、最大 2,000 ラウンド。forward fold の学習月（1〜10 月）のうち 10 月で早期打ち切りし、
  1〜9 月で学習したモデルで 11〜12 月を予測する（検証月は一切見ない）。
- **混合**: LIRF マッチ行だけ `pred = (1 − p)·oof + p·mvt_minus_sched`。他の行は base のまま。
  base の model A は流用行も含めて学習しているので、この混合は流用を二重に数える側に偏る（保守的な近似）。
- **対照**: `p` を LIRF マッチ行の中でシャッフルした混合（分類器の中身を壊し、流用率の平均だけを残す）。

### 本実装に進む条件（すべて満たす）

1. 分類器の検証 AUC を記録する（ゲートにはしない。P1 の 0.93 は未マッチ行の数値で、ここには移せない）。
2. 混合が `prc.compare` の規則で base に対して **ADOPT**（全行と K=200 の 95 % CI がともに改善側でゼロを除外）。
3. シャッフル対照は ADOPT に**ならない**（ならば、効いているのは平均的なずれ補正で、分類器ではない）。

満たさなければ、この方向は閉じて記録する。満たせば、段階 2（本実装: model A を流用行を除いて学習し直した上での混合、
forward と jan での 3 群比較）の計画を別途書いてから進める。
