# 外部特徴量: OSM のスタンド位置から滑走路端までの距離 — 事前登録（2026-09-28）

結果を見る前に書く。判定規則・群・列の定義は測定を始めた後に変えない。

## 0. 動機と、最初に訂正すること

- スタンドの情報は今、スタンドのカテゴリ（識別子）と、スタンド×滑走路ごとのラベル統計（ref_*）だけで入っている。
  どちらも**学習で見たスタンドにしか値がない**。距離は物理量なので、初めて見るスタンドにも値が付く唯一の記述子。
- 対象の大きさ（実測）: 2025 年に一度も出てこないスタンドのランキング行は **1,589 行（0.46 %）**
  （EDDM 103〜108 の 1,182 行、EDDF 300 行、他は各 0〜58 行）。スタンド×滑走路の組が 2025 年に 30 件未満の行は
  12,950 行（3.76 %）だが、こちらはスタンド自体は既知で、既存の代替（空港×滑走路×時間の中央値）が効いている。
  ユーザーへの前回の説明で「新しいスタンドが 3.76 %」と書いたのは誤りで、正しくは上の 0.46 %。
- 見込み: 新しいスタンドの行だけなら全体で 0.2 s 程度。通常の fold ではほぼ見えないので、専用の模擬テストで測る。

## 1. 列

`osm_stand_rwy_km` = スタンドの OSM 位置（`aeroway=parking_position` の `ref` を正規化して照合、同じ ref の要素は平均）
から、出発滑走路の端（`RUNWAY_mvt` と同名の端、OurAirports `runways.csv`）までの大圏距離（km）。照合できなければ null。

- ライセンス: OSM は ODbL（オープン、派生データベースは share-alike）、OurAirports はパブリックドメイン。どちらも賞の条件を満たす。
- 照合率（行ベース、2025 / 2026）: LIRF 99.0 / 98.5、EGLL 98.4 / 98.2、LSZH 96.4 / 96.5、EHAM 94.6 / 95.6、
  LEBL 89.7 / 89.1、EDDF 70.4 / 72.9、LTFM 99.2 / 98.9、LEMD 98.8 / 98.7、LFPG 96.9 / 98.1、EDDM 57.4 / 57.6 %。
  全体 90.7 / 91.5 %。どの空港も 2025 と 2026 で差が小さい。
- 2025 年に一度も出てこないスタンドのランキング行 1,589 行のうち **1,122 行（71 %）** が照合できる
  （EDDM 103/104/105/108 の 873 行、EDDF J5/J10 の 202 行ほか）。
- 取得経路: EDDF, EGLL, EHAM, LEBL, LIRF, LSZH は Overpass、EDDM, LEMD, LFPG, LTFM は Overpass がこの環境から
  接続を切られ続けたため OSM 本体 API の `map`（空港の矩形を 3×3 に分割）。どちらも同じ OSM データ。

## 2. 群

すべて `configs/main_gap.yaml`（v14）＋ `folds: [forward]`。

| 群 | 変更 |
|---|---|
| base | なし（`afe_forward_base-27b685dad7` をそのまま使う: 同じ設定・同じコード経路で、決定的に同じ OOF になる） |
| noise1 | ハッシュ列 1 本 |
| dist | `osm_stand_rwy_km` |
| base_u | `sim_unseen_stands: 0.2` |
| noise1_u | `sim_unseen_stands: 0.2` ＋ ハッシュ列 1 本 |
| dist_u | `sim_unseen_stands: 0.2` ＋ `osm_stand_rwy_km` |

`sim_unseen_stands: 0.2` は、(空港, スタンド) の CRC32 で選んだ 20 % のスタンドについて、**学習行をすべて捨てる**。
そのスタンドはカテゴリとして学習に現れず、ref_* も付かない。2026 年に新しいスタンドが出てきたときと同じ状態になる。

## 3. 判定

**採用候補** = 次の 3 つをすべて満たす。

1. **初めて見るスタンドで改善**: 模擬テスト（*_u 群）の検証行のうち、捨てたスタンドの行（以下「未知スタンド行」）だけで
   base_u → dist_u の差を行単位 bootstrap で測り、K=0 と K=200 の 95 % CI がともに改善側でゼロを除外する。
2. **列を足しただけではない**: 同じ未知スタンド行で、noise1_u → dist_u の K=200 の 95 % CI が改善側でゼロを除外する。
3. **既知のスタンドを悪くしない**: 通常の forward で `prc.compare base dist` が「B is worse」（K=0 の CI が悪化側でゼロを除外）
   にならない。通常の fold で改善を示すことは求めない（対象の行がほとんどないため）。

補足（判定に使わない）: 未知スタンド行の空港別、照合できた行／できなかった行別、通常 fold の lane 別。

## 4. 範囲

本番（`configs/main_gap.yaml`）と提出は変えない。

## 5. 追記（2026-09-30、確認の測定の前に）: 3 fold での確認

段階 1 の 3 条件を満たしたので、本番に渡す前に既知のスタンドでの効果を fold を増やして確かめる。

- 群: `osm_full_base` / `osm_full_noise1` / `osm_full_dist`。すべて `main_gap` ＋ `folds: [jan, jul, forward]`
  （`jul_fwd` は `overall` に入らない fold なので省く）。
- **本番への推奨**: `prc.compare osm_full_noise1 osm_full_dist` が ADOPT（全行と K=200 の CI がともに改善側でゼロを除外）、
  かつ `prc.compare osm_full_base osm_full_dist` が「B is worse」にならないこと。
- そうでなければ「未知スタンドへの頑健性のための任意採用。平均の LB 効果は測定限界以下」と記録して、判断を渡す。
