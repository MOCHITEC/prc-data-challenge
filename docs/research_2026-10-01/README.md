## 1. NN・線形・ブレンド

- **文献と他チーム**: 表形式データで GBDT に NN を足したときの改善は、相対 0.2〜1% が普通。
  - PRC 2024 の 2 位チームでは、MLP と SAINT の重みが実質 0 だった。
  - 2026 年に NN のブレンドで改善を報告した公開チームは無い。
  - 詳細はチームの既存判定（`competitor_research_2026-09-21/plans/00-master-candidate-list.md` の「Refuted in P10」）と同じ。
- **実測は中止**: v12 の上で MLP・Ridge のブレンドを測るスクリプトは動いた（合成データで確認）。v23 の段階では基準が古いので、実データでの測定は途中で止めた。
- **結論**: v23 は GBDT を 3 本混ぜており、多様性はそこで入っている。NN を 4 本目に足しても 1 秒未満と見積もる（推論）。

## 2. 日付ずれ（rollover）

学習 2025 年に y > 72,000 秒の出発便は 16 行（LIRF 14、LSZH 1、LFPG 1）。

### 2.1 仕組み

- **LIRF**: 12 行すべてがローマ現地時刻で次の形になる。
  - 現地日付(BLOCK) = 現地日付(SCHED)、現地日付(MVT) = 翌日。
  - 解釈: オフブロック時刻を「予定時刻 ±12 時間の窓」に置く処理。
  - 実際の遅れが 13.7 時間を超え、予定時刻の書き写しでない行は 12/12 が日付ずれ。
  - 遅れ 1〜5 時間で深夜 0 時をまたいだ非書き写し行 33 行は、すべて正しい日付で記録されている。
  - LIRF→LFPG の ITY332 は、LFPG 側の着陸記録と `AOBT_3` で直接確認できた（`rollover/arrivals/`）。
- **LIRF 以外**: 前日に一度プッシュバックしたが飛ばず、その記録が残ったものと推論（`rollover/nonlirf/`）。
  - LFPG EJU983W は前日に同じ便名の行が無く、同じスタンドに 32.5 時間とどまっていた。
- **他の 9 空港**では、ms ≥ 12 h の行 595 行で日付ずれは 0。

### 2.2 2026 年に予測時に見える手がかり

- **LIRF の NM レコード無し便で ms ≥ 8 h**: 正解は「書き写し（y = ms）」か「日付ずれ（≒ 87,000）」の二択。2025 年は 50 行中、普通の行は 0。
- **ms 帯ごとの日付ずれ率（2025 年）**

  | ms 帯 | 日付ずれ / 行数 |
  |---|---|
  | 12〜14 h | 0/9 |
  | 14〜16 h | 2/7 |
  | 16〜28 h | 9/12 |

- **書き写しと日付ずれを分ける手がかりは見つからなかった。** 試したのは次のとおり。
  - 便名の文字の重複、スタンド、滑走路
  - 到着便、ID の並び、行順、秒の付き方
- **v11 の失敗の理由**: 11 行に一律 p = 0.379 を当てていた。2025 年の leave-one-month-out でも `ms` をそのまま予測するより悪い（6.34e9 対 5.77e9）。帯ごとに p を変えれば 3.94e9 になる。
- **ただし 2025 年の二択モデルは v11 の結果と整合しない。** 2026 年のこの層の性質が違う可能性がある。適用は ±5〜10 秒の賭けで、**保留**。
- **ITY340（2026-07、NM レコード有り）**: NM の到着記録と翌朝の折り返し便から、実際には 07-16 に飛んでおり、ずれているのは MVT の日付（+1 日）。
  - 正解は約 86,460 秒の可能性が高い。
  - v23 は proxy（86,340）と LOBT の範囲制限ですでに 86,000 前後を予測しているはず（未確認）。
- **LIRF 以外**: 最良の条件（NM レコード無しで定刻）でも日付ずれ率は 0.24%。効果は ±0.05 秒で、**何もしない**。
- **到着便**: 2026 年の到着便に日付ずれは 0 行。手がかりにならない。

### 2.3 上限

- 2025 年 Jan+Jul の 7 行を 2026 年の代理にすると、「全部分かれば」252.4 → 約 196。
- ただし −44 秒は LFPG の 1 行による。LIRF だけなら −10.6 秒。
- LB 252 から逆算すると、8.6 万秒外しの行は 2026 年に多くても 1 行程度。

### 2.4 グレーな抜け道（使っていない）

- グリッド空港（EDDM・EGLL・LFPG・LIRF・LTFM）では、MVT と BLOCK の秒が逆符号の ±6 秒ジッタで、和が {−1, 0} になる（99.95〜100%）。
- LTFM・LFPG の学習側では、ID の並びが実時刻に沿う。
- どちらも空欄化された列の部分的な漏れ。採点処理を探る行為ではないが、価値も小さい（§3）。

## 3. 秒の痕跡で精度は上がるか → 上がらない（実測）

`rollover/seconds_lattice.py`。

- グリッド空港では `y − 2·oM mod 60 ∈ {0, 1}` が 108 万行中 99.99% で成立する。
- Jan+Jul（6 万行）で、予測を格子上の事後平均に寄せた結果:

  | 予測 | RMSE |
  |---|---|
  | 補正なし | 296.85 |
  | 格子に寄せる | 296.95（+0.10） |
  | 余りを 1 つに特定できた場合 | 296.99（+0.14） |

- 理由: 格子の間隔（約 30 秒）が予測誤差（200〜300 秒）よりずっと小さく、情報が乗らない。

## 4. 普通の行の大誤差群

genuine = BLOCK が既知の時計の写し（±60 秒）でも日付ずれでもない行。Jan+Jul 2025 のマッチ行で 230,335 行、誤差の 74.5%。

| 群（genuine の SSE 比） | 結論 | 取れる見込み |
|---|---|---|
| BLOCK が AOBT_3 より 10 分超早い（34%） | 遅延便が早めに押し出して待つ。約 90% は ADS-B 無しでは予測不能。早押し率の集計は −0.1〜−0.3 秒 | 小 |
| 長い taxi ≥ 30 分（32%） | 日や時間帯の体制ではなく行ごとの現象。中身は上の群とほぼ同じ | 群としては 0 |
| 遅延 30 分〜3 h（40%） | ばらつきが大きいだけで、帯域ごとの偏りや校正ずれは 0。`nm_blk2land_excess` が −0.3（v23 換算 −0.05〜−0.2） | 小 |
| LTFM の ADS-B 残差 | **見送り**。adsb.lol に LTFM の地上 fix が 2025・2026 とも 0（6 日の標本で確認）。v23 の c = 0 を維持 | 0 |
| 空港構造 | LTFM・LFPG で空港専用モデルを全体モデルと半々で混ぜると −4.2 / −4.1 秒（両月で改善）。LTFM の滑走路運用特徴量は −2.3 秒 | −0.3〜−1.0 秒 |

追加でわかったこと:

- **LTFM の AOBT_3 の作られ方**: 「MVT − 滑走路ごとの固定タクシー時間（19 分 / 24 分）」で作られ、40% の行がちょうどその値。LTFM の誤差は時計のずれではなく実タクシー時間そのもの（`errgroups/clockgap/`）。
- **2026 年 1 月の EHAM の荒れ方**: 1/2〜7 は到着便の taxi-in 残差の日平均が +1,600 秒で、2025 年の最大の 15 倍（`errgroups/longtaxi/flagged_days_2026.csv`）。
  - 決定木は学習範囲の外へ外挿しないので、v23 の予測を確認する必要がある。
  - 外していた場合の損失は、既存の試算で +3〜6 秒。
- **同時期の窓特徴量（tx_mma）**: 近傍の他便の MVT − AOBT_3 を、中心窓・前方窓・±2 時間窓で、空港の平常値との比として取る。窓内の NM 未マッチ率なども加える。
  - 簡易基準に対して −1.30 秒 [−2.22, −0.37]、seed を変えると −1.60 秒 [−2.36, −0.76]。
  - 空港別: EHAM −10.0、LEMD −3.2、LFPG −3.1。LIRF +3.7、LTFM +1.2 は悪化。
  - 日単位の列と ARR taxi-in の窓は効かない、または長い taxi を悪化させる（`errgroups/longtaxi/`）。

## 5. 結論

首位との差（約 33 秒）を詰める決め手は、この日の範囲では見つからなかった。v23 に上積みできる候補と、その見込みは次のとおり。

| 優先 | 施策 | v23 での見込み |
|---|---|---|
| 1 | tx_mma 群（L5、§6） | −0.3〜−1.2 秒 |
| 2 | LTFM・LFPG の空港専用モデルを 0.5/0.5 で混ぜる（P11 の初実測。v23 の 4 本目の member） | −0.3〜−0.8 秒 |
| 3 | LTFM 限定の滑走路運用特徴量（到着の混在・±30 分シェア） | −0.2〜−0.3 秒 |
| — | EHAM 2026 年 1 月の予測分布の確認（保険） | 損失の回避 |
