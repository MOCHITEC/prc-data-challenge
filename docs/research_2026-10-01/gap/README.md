# 首位チームとの差の調査（2026-10-02）

対象は我々の v32（LB 251.7333、33 位）と首位 strong-crane（219.64）の差で、MSE にして 15,128 s²。
86,400 秒外しの行に換算すると 0.70 行分にあたる。調査は 3 観点で、スクリプトはこのフォルダの `lb/`、`public/`、`decomp/` にある。
入出力パスはスクラッチ領域を指している。[S] は実測または出典を読んだもの、[X] は推論。

## 結論

差の大きな源は「各便が実際にスタンドを離れた時刻をどれだけ多くの行で観測できているか」にある。モデルの調整ではない。

- **上位勢の伸び方**: 新しい観測を 1 つ入れて 15〜40 秒伸び、モデル調整は 1 回 1 秒未満 [S]。
- **我々の ADS-B 取り出しの現状** [S/X]

  | 段階 | ランキング行に占める割合 |
  |---|---|
  | 地上 fix がある | 約 71% |
  | 駐機区間を検出できた | 約 43% |
  | プッシュバックを検出できた | 約 21% |

  地上 fix はあるのに時刻が取れていない行が多い。
- **公開されている上位相当の実装（smart-jigsaw、`yookeew/dumb-puzzle`）** [S]
  - 「スタンド上で最初に見えた時刻」（プッシュバック時にトランスポンダが入る）を off-block とみなす appear tier を使う。
  - スタンド座標は X-Plane Scenery Gateway（2,838 スタンド）から取る。
  - ADS-B だけで −19 秒。
- **我々の検出の取りこぼし** [S]
  - 後退動作を条件にしているので、「最初の動きが前向き」の行（空港により 20〜42%）と「最初に見えたとき既に動いていた」行（18〜27%）を落としている。
  - LFPG は地上 fix が 58% あるのに、スタンドの検出は 3%。
- **我々が使っていない観測: OPDI の flight events**（exit-parking_position = プッシュバック）[S]
  - 上限の取得率は LSZH 79%、EDDF 47%。adsb.lol の EDDF は 2〜8% なので、その穴を埋める。
  - Discord（09-09、二次情報）で open data と認定されたと伝えられている。ライセンスは要確認。
- **時系列（LB）** [S/X]
  - 2・3 位は 09-17 時点で既に約 242 だった（我々の ADS-B 無し最良は 279）。
  - 首位は 09-26 に ADS-B 規模（−17 秒）の一歩があり、その後 0.05〜0.07 U の改良を 8 回積んでいる。
  - 上位はそれぞれ別の時計や観測を持っていると見る。
- **最終評価の別セットは告知が無い** [S]。LB のベストがそのまま最終になる見込み。提出は 09-30 から MinIO CLI のみ。
- **このまま止まった場合** [X]: 10-11 の予測は 1 位 217〜218、20 位 225〜230、30 位 235〜240。我々は 45〜55 位まで下がる見込み。

## 内部予算（LB 尺度の MSE、合計 63,370。推定 [X]）

| 成分 | 推定寄与 |
|---|---|
| マッチ行 | 38,000〜48,000 |
| 　うち LIRF | 約 9,300 |
| 　うち LTFM（ADS-B 無し） | 約 7,400 |
| 　うち LFPG | 約 6,200 |
| 　うち ADS-B が効く 7 空港 | 約 15,800 |
| 未マッチ行（1.5%） | 15,000〜25,000 |

全空港・全行を ADS-B 並みに観測できた場合の価値は約 10,000〜12,000 s²（差の 65〜80%）。
LTFM は地上 fix が 0 なので、現実に届くのは LFPG・LIRF・EDDF の改善と OPDI で、約 3,000〜5,000 s²。

## 推奨（優先順）

1. **ADS-B 検出の第 2 段**: appear tier（スタンドで最初に見えた時刻）を加え、前向きの初動や既に動いていた行からも動き出し時刻を取る。スタンド座標を Gateway で補う。対象は EHAM・LEBL・LSZH・LFPG・LIRF・EDDF。
2. **OPDI の exit-parking_position を off-block の観測源に足す**（LSZH・EDDF）。先にライセンスと 2025 年での精度を確認する。
3. **未マッチ行専用の ADS-B 残差**: AOBT_3 が無い行では ADS-B が唯一の時計になる。v26 の分解では、LB の変化の 86% が未マッチ 2,416 行に集中していた。
4. 保険: EHAM・EDDF・LFPG の未マッチ行で ms が 3 万〜9.6 万秒の約 27 行を、ADS-B の前日駐機と照合する。

1〜3 はいずれも ADS-B の素材（adsb.lol の取り込み済みデータ）がある環境での再学習が必要。
