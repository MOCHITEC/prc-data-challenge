落ちなければ、そのガードは思い込みで入れたか、テストが弱いかのどちらか。

## 通ってしまった 3 件の原因

いずれも**ガードは本物だがテストが弱かった**。バグ自体は実在する。

- **G2**: テストが `num_rounds=30 / early_stopping=10` で、早期打ち切りが一度も発火していなかった。
  発火しなければリークしても打ち切り位置は変わらず、差が出ない。
  → `num_rounds=400` にし、**「打ち切りが実際に発火したこと」を先に assert** した上で、
  評価側のラベルを空にしても打ち切りラウンド数が変わらないことを検査するよう変更。
- **G5**: テンプレートも予測も `int64` で、そもそも dtype 不一致が発生していなかった。
  → 公式ファイルと同じ **float64 テンプレート × int64 予測**、かつ ID 順をわざと崩した検査を追加。
- **G7**: 合成データでは 2 モデルの担当行の並びが偶然一致し、位置代入でも正解になっていた。
  → **マッチ行と未マッチ行を交互に並べた**フレームを作り、行順を入れ替えても各 ID の予測が
  変わらないことを検査するよう変更。

強化後は 3 件とも変異で落ちることを再確認済み。

## 結論

**9 件すべて実バグに対する正当なガードで、いまは全件テストで保護されている。**
削除してよいのは、この表に載っていないコード（提出経路に乗らない補助ツール類）のみ。
